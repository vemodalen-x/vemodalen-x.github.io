# Transformer 速查宝典：从名称列表到六层设计空间

## 来源审计

- 中文文章：[《Transformer速查宝典：模型、架构、训练方法的论文都在这里了》](https://mp.weixin.qq.com/s/uBv8t2hd0WS4aAqUuAyBhw)，机器之心，2023-08-13，正文约 1.5 万字。
- 英文原文：[Transformer Taxonomy (the last lit review)](https://kipp.ly/p/transformer-taxonomy)，kipply，2023-03-30。
- 中文版说明覆盖 21 个模型、11 种架构变化、7 种预训练后处理、3 种训练技术和 5 个其他主题。
- 英文原文实际列出 22 个模型；中文版漏掉 `Jurassic J1-Grande v2`。原文还明确排除了系统/性能和对齐研究，因为作者希望单独展开。

本笔记已完整读取中文正文并逐段对照英文原文的分类和关键陈述。**这只代表文章层达到语义精读，不代表文中链接的数十篇论文都已经逐篇精读。** 论文链接继续承担阅读目录作用，只有单独完成论文证据表和实验后才能提升为论文级知识。

## 一句话结论

文章真正有价值的不是“记住哪些模型最大”，而是揭示：**一个语言模型是多层选择的组合，不是一个名称或参数量。比较两个模型时，至少要拆开基础模型、架构、预训练、后训练、推理采样和系统增强六层；性能差异可能来自其中任何一层。**

## 六层设计空间

| 层 | 核心问题 | 文章中的代表内容 | 不能混淆的边界 |
| --- | --- | --- | --- |
| 1. 基础模型 | 参数规模、层数、隐藏维度和模型族是什么？ | GPT-3、Gopher、PaLM、LLaMA、BLOOM 等 | 模型名是多种选择的打包结果，不是因果解释 |
| 2. 架构 | 信息怎样流动，计算和内存怎样分配？ | MQA、稀疏注意力、MoE、RoPE、ALiBi、RMSNorm、SwiGLU | 架构质量必须与规模、硬件、上下文和任务一起评估 |
| 3. 预训练 | 数据、token 数、目标、批量、学习率和计算预算是什么？ | GPT-3 配方、Chinchilla scaling、MuP、PHF | 参数更多不自动更优；数据和训练 token 可能是主要变量 |
| 4. 后训练 | 怎样把基础分布变成可用行为？ | SFT/FeedME、FLAN、RLHF/PPO、CAI、Minerva、Codex | 后训练能改变接口和偏好，但不能凭空补齐底层知识与可靠性 |
| 5. 推理采样 | 怎样从 logits 生成、搜索或补全？ | temperature、top-k、top-p、beam search、FIM、CoT | 生成更长或更“像推理”不等于事实更正确 |
| 6. 系统增强 | 模型怎样接入外部信息和行动？ | RETRO、WebGPT、Toolformer、多模态和工具使用 | 检索、工具、权限、缓存和服务性能属于系统，不应全归功于模型参数 |

这六层比原文四个大类更适合工程判断。原文把模型、算法、训练过程、提示技术、采样和系统能力放在相邻列表中，便于发现论文，却容易让初学者误以为它们是同一层的可替换选项。

## 22 个模型的历史坐标

| 组 | 模型 | 主要学习价值 |
| --- | --- | --- |
| 密集通用模型 | GPT-3、Gopher、Chinchilla、PaLM、OPT、LLaMA、Jurassic J1-Grande v2 | 从“扩大参数”走向数据和计算共同最优；观察训练配方怎样逐渐标准化 |
| 闭源与行为接口 | GPT-4、GPT-3.5、Anthropic LM、LaMDA | 架构披露有限；评测、SFT、RLHF、对话接口和安全过程成为主要公开信息 |
| 开放模型与基础设施 | GPT-NeoX、GPT-J、BLOOM、GLM-130B | 理解开放权重、训练栈、多语言 tokenizer、量化与可复现实验 |
| 稀疏专家 | GLaM、Switch | 总参数量和每 token 激活参数量必须分开；路由和负载均衡决定实际成本 |
| 检索、代码、科学、多模态与智能体 | RETRO、AlphaCode、Galactica、Flamingo、Gato | 能力可来自检索库、领域数据、视觉编码器、采样筛选或动作 token，不只来自扩大语言模型 |

必须保留的历史判断：

1. GPT-3 把大规模自回归预训练、上下文学习和一套后来广泛复用的训练配方连接起来。
2. Chinchilla 说明在固定计算下，参数量和训练 token 的分配会决定结果；“最大参数”不是唯一轴。
3. RETRO 说明参数知识之外还可通过训练和推理时检索扩展信息来源。
4. Flamingo 与 Gato 展示把视觉或连续动作编码接入序列模型的早期路线。
5. GLaM 与 Switch 说明总参数规模、激活参数和每 token 计算不是同一个数。
6. 开放模型的价值不仅是权重，还包括训练日志、代码、数据说明和复现边界。

## 11 类架构变化

| 变化 | 解决的问题 | 关键代价或判断 |
| --- | --- | --- |
| MQA | 多个查询头共享 K/V，减少 KV cache 和解码带宽 | 速度收益可能伴随质量损失；后来 GQA 在 MHA 与 MQA 之间折中 |
| 稀疏注意力 | 避免所有 token 两两注意 | 稀疏模式本身是先验，可能漏掉任务需要的依赖 |
| MoE | 每个 token 只激活部分专家，扩大容量而不同比例扩大计算 | 路由、负载均衡、通信和专家塌缩成为新问题 |
| FlashAttention | 用 IO 感知分块避免物化完整注意力矩阵 | 它保持精确注意力语义，更接近内核/系统算法优化，而非新的注意力关系 |
| Encoder-decoder | 分离输入编码与输出生成 | 翻译和长输入短输出合理；持续对话中的参数共享和 KV 缓存更复杂 |
| 平行注意力 | 并行计算注意力和 MLP，提高算术强度 | 收益依赖硬件和具体实现，不只由数学结构决定 |
| GeGLU/SwiGLU/SoLU | 改变前馈层非线性、门控或可解释性 | 需比较参数量、稳定性、吞吐和任务收益 |
| DeepNorm/RMSNorm | 改善深层训练稳定性或降低归一化成本 | RMSNorm 去掉重中心化，按均方根缩放；不是“数值均值的平方根” |
| RoPE | 将相对位置信息编码进 Q/K 旋转 | 长度外推仍受训练分布和缩放策略影响 |
| BPE/SentencePiece | 将文本映射为有限子词词表 | BPE 是分词算法；SentencePiece 是可直接处理原始 Unicode 的工具/框架，也能实现 BPE，二者并非严格二选一 |
| ALiBi | 通过距离偏置支持更长长度外推 | 外推表现需按任务和长度实测，不等于无限上下文 |

三个重要工程连接：

- MQA 的目的不是“更聪明”，而是减少自回归解码时 K/V 读取；[GQA](https://arxiv.org/abs/2305.13245)后来用多个 K/V 组在质量和速度间折中。
- [FlashAttention](https://arxiv.org/abs/2205.14135)和[FlashAttention-2](https://arxiv.org/abs/2307.08691)提醒我们：复杂度公式相同，内存层级、分块和工作划分不同，真实吞吐也会相差很大。
- [RMSNorm](https://arxiv.org/abs/1910.07467)的核心是放弃 LayerNorm 的重中心化，只保留按 root mean square 的重缩放不变性，从而简化计算。

## 后训练、训练与推理条目

### 七种预训练后处理

| 条目 | 应怎样理解 | 证据边界 |
| --- | --- | --- |
| RLHF + PPO | 偏好数据 -> 奖励模型 -> 受 KL 约束的策略优化 | 奖励模型会偏，PPO 复杂且可能不稳定 |
| Constitutional AI | 用一组原则产生自我批评/修订数据，再以 AI 偏好辅助训练 | 原则文本、反馈模型和评测仍是人为设计 |
| Minerva | 在数学和科学数据上继续训练 PaLM | 领域数据、格式保留和评测共同贡献结果 |
| Codex | 在代码数据上微调并用 HumanEval 评估 | 代码能力来自数据和接口，不只来自模型规模 |
| 对 CoT 输出微调 | 用推理轨迹作为训练目标 | 原作者没有给出确定论文，属于低置信线索，不提升为方法结论 |
| FeedME / SFT | 用人工示范把基础模型变成指令接口 | 模仿示范不自动保证事实、安全或分布外泛化 |
| FLAN | 将多任务数据改写为指令格式，提升零样本迁移 | 任务覆盖和模板设计影响泛化结论 |

### 三种训练技术

1. **超参数与缩放：** 学习率、批量、warmup、数据 token 和模型规模共同决定训练轨迹；只复制一个最终超参没有迁移保证。
2. **PHF：** 在预训练数据中加入好/坏条件信号，是把人类偏好提前注入预训练的尝试；原文也指出简单过滤并非总是更好。
3. **MuP：** 目标是让部分最优超参数可跨模型宽度迁移，减少大模型直接扫参成本；仍需要检查实现是否满足参数化假设。

### 五个“其他”主题

- **CoT：** 为模型提供额外生成计算和可读轨迹；轨迹可能合理但答案仍错，不能当作忠实内部解释。
- **工具使用：** 将搜索、计算和行动移到外部系统；关键变成工具正确性、权限、状态和结果验证。
- **FIM：** 通过数据重排学习中间补全，尤其适合代码编辑；它说明数据目标可以直接创造产品能力。
- **Top-k / top-p / beam：** 改变从 token 分布到序列的搜索与随机性；应按任务质量、多样性、延迟和重复率评测。
- **Tail Free Sampling：** 原文自己承认缺少良好基准，因此只保留为候选方法，不默认优于 top-p。

## 需要纠正或降级的陈述

1. **21 与 22：** 中文版漏掉 `Jurassic J1-Grande v2`，因此“21 个模型”不是原文完整清单。
2. **FlashAttention 分类：** 它改变注意力实现和 IO，而不改变精确注意力的数学输出；更适合放在算法与系统性能层。
3. **RMSNorm 描述：** 应是输入平方的均值再开根号，而不是先求输入均值再开根号。
4. **BPE vs SentencePiece：** [SentencePiece](https://github.com/google/sentencepiece)同时支持 BPE 和 unigram；正确比较应拆成分词算法、预处理、字节/字符处理、词表和实现框架。
5. **GPT-4 类似 Flamingo：** GPT-4 技术报告没有公开足够架构细节，“似乎用类似 Flamingo 的方式训练”只能标为作者推测。
6. **模型最大、开源最大等排名：** 都是 2023 年时间快照，不能用于当前模型选择。
7. **CoT 与工具：** 能力提升取决于任务、训练、工具反馈和评测；不能从一篇早期论文外推为普遍可靠性。
8. **来源置信度不一：** 原文既有论文事实，也有作者直觉、博客、项目文档和“忘记是哪篇论文”的线索，入库时必须分级。

- **对齐与治理：** 数据许可、偏好数据、红队、安全评测、拒答、提示注入、监控和责任边界。

## 推荐学习顺序

1. 先用 LLMs-from-scratch 打通 token 到 logits 的最小因果链。
2. 读原始 Transformer、GPT-3 和 Chinchilla，理解基础架构与缩放配方。
3. 选 MQA/GQA、FlashAttention、RoPE、RMSNorm、SwiGLU 各做一张“机制、收益、代价”卡。
4. 比较 SFT、RLHF/PPO、CAI 和 DPO，区分示范、偏好、奖励和策略更新。
5. 用 RETRO、WebGPT、Toolformer 理解参数、检索和行动工具的边界。
6. 最后选择两个真实模型，用上面的六层模板和同一组私有任务做对照，不以公开榜单代替实测。
