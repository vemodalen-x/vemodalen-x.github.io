# QLoRA：在有限显存下进行参数高效微调

## 一句话结论

QLoRA 的关键不是简单地“用 4 位训练模型”，而是把三件事分开：**冻结基础模型的存储精度、前向与反向传播的计算精度、真正被更新的参数集合**。论文用 4 位 NF4 保存基础权重，计算时反量化到 BF16，只训练 LoRA 适配器，从而把 65B 模型的微调显存降到单张 48GB GPU 可承受的范围，并在其评测范围内接近 16 位 LoRA 的效果。

对我的知识库更重要的结论是：**微调成本下降，不代表问题定义、训练数据和评测成本消失。** QLoRA 是稳定行为适配的工程手段，不是给模型补充最新事实、修复检索或替代产品评测的万能方案。

## 论文信息

- 论文：[QLoRA: Efficient Finetuning of Quantized LLMs](https://arxiv.org/abs/2305.14314)
- 作者：Tim Dettmers、Artidoro Pagnoni、Ari Holtzman、Luke Zettlemoyer
- 提交时间：2023-05-23
- 官方实现：[artidoro/qlora](https://github.com/artidoro/qlora)
- 研究问题：能否显著降低大模型微调的显存需求，同时尽量保留 16 位微调的任务性能？

## 先理解 LoRA，再理解 QLoRA

全参数微调需要为大量参数保存权重、梯度和优化器状态，显存成本很高。LoRA 冻结原始权重，在部分线性层旁加入低秩增量矩阵，只更新这些小型适配器，因此显著减少可训练参数和优化器状态。

但标准 LoRA 仍通常以 16 位保存冻结的基础模型。QLoRA 继续压缩这一块最大的静态开销：

```text
输入
  ↓
冻结的 4-bit NF4 基础权重
  ↓ 计算时反量化
BF16 前向 / 反向计算
  ↓ 梯度穿过基础模型，但不更新基础权重
更新 LoRA 适配器
  ↓
保存很小的任务适配器，而不是一份新的完整模型
```

这里最容易混淆的是：

| 层次 | QLoRA 中的做法 | 作用 |
| --- | --- | --- |
| 存储精度 | 冻结基础权重使用 4-bit NF4 | 降低基础模型常驻显存 |
| 计算精度 | 计算时将量化权重反量化到 BF16 | 保留较稳定的前向和反向计算 |
| 可训练参数 | 只更新 LoRA 适配器 | 减少梯度与优化器状态 |

所以，QLoRA 并不是对 4 位离散权重直接做普通全参数更新，也不能据此推导出“4 位全参数训练等同于 16 位训练”。

## 三项核心技术

### 1. NormalFloat 4-bit（NF4）

NF4 是针对近似零中心正态分布的神经网络权重设计的 4 位数据类型。它使用非均匀的表示区间，让有限的 16 个离散值更贴合权重分布。论文实验中，NF4 优于常见的 FP4 和 Int4 方案。

边界：所谓“信息论最优”依赖权重分布与量化假设，不能理解为任何模型、任何层、任何任务下都绝对最优。

### 2. Double Quantization（双重量化）

分块量化需要保存每个块的缩放常数。双重量化继续量化这些常数，论文报告平均可再节省约 0.37 bit/parameter；对 65B 模型约等于数 GB 显存。

工程判断：大模型优化不能只看主要张量。缩放常数、优化器状态、激活峰值和序列长度都可能决定训练是否能装进显存。

### 3. Paged Optimizers（分页优化器）

长序列或梯度检查点会造成短时显存峰值。分页优化器利用 NVIDIA Unified Memory，在峰值时把部分优化器状态转移到 CPU 内存，以降低显存溢出概率。

边界：它解决的是峰值管理，不是免费显存。CPU 与 GPU 之间的数据迁移可能降低速度，不能替代批大小、序列长度和检查点策略的测量。

## 实验设计与关键结果

论文训练了 1,000 多个模型，覆盖约 80M 到 65B 参数、LLaMA 与 T5 系列以及 8 个指令数据集。作者使用监督式交叉熵训练，并比较量化类型、LoRA 配置、模型规模、数据集和评测方式。

值得保留的结果：

1. 在论文评测范围内，NF4 配合双重量化的 4 位 LoRA 可以接近 16 位 LoRA 的结果。
2. LoRA 不应只加在少数注意力矩阵上。论文消融发现，把 LoRA 用于 Transformer block 的全部线性层，是匹配 16 位表现的重要条件；覆盖哪些层比单独增大 rank 更关键。
3. QLoRA 让 65B 模型能够在单张 48GB GPU 上进行微调。这个结果说明显存门槛显著下降，不代表所有消费级显卡都能训练 65B。
4. 模型规模、数据适配度和数据质量共同影响结果，不能把提升全部归因于量化方法。

## 数据：不是越多越好，而是要与目标匹配

论文的一个重要观察是，小而高质量的 OASST1 数据子集可以训练出很强的聊天模型；更大的 FLAN v2 数据在 MMLU 上表现较好，却没有在聊天评测中同样领先。

更准确的个人结论不是“少量数据永远胜过大量数据”，而是：

- 数据必须与目标任务和评分标准匹配。
- 去重、准确性、回答风格和边界样本比盲目扩充数量更重要。
- 通用知识基准和聊天体验可能近似正交，单一分数不能代表产品效果。
- 在训练前应先保留独立评测集，防止把训练样本的熟悉度误认为泛化。

## 评测：模型裁判有用，但会带偏见

论文同时使用 MMLU、Vicuna 问题集、OpenAssistant 问题集、GPT-4 评价和人工评价。对我最有用的不是某个排名，而是以下评测教训：

1. GPT-4 评价存在明显的顺序偏差，倾向于排在前面的答案。论文建议交换 A/B 顺序并取平均。
2. 成对比较和 Elo 排名通常比模糊的 1 到 10 分绝对评分更稳定。
3. 系统总体排名的一致，不代表逐样本判断可靠；模型裁判还可能偏爱与自己相似的输出。
4. 定量排名必须配合人工失败分析。作者主动“挑坏例子”，发现幻觉、无理由拒答、提示注入、数学推理错误和心智理论错误。

我的评测协议：

```text
固定私有题集
  + 明确评分规则
  + 基础模型 / 提示词 / RAG / QLoRA 对照
  + A/B 双顺序模型评价
  + 人工抽检分歧样本
  + 按错误类型归档失败
```

## 论文没有证明什么

1. 作者没有在 33B 和 65B 上完成 QLoRA 与 16 位全参数微调的全面等价比较；相应规模主要比较的是 4 位 LoRA 与 16 位 LoRA。
2. 论文没有覆盖所有基准、语言、领域、部署硬件和参数高效微调方法。
3. 聊天评测排名不能证明事实可靠、安全、抗提示注入或适合高风险场景。
4. 结果来自 2023 年的模型、数据和软件栈，今天执行时需要重新核验 Transformers、PEFT、bitsandbytes、CUDA 与驱动兼容性。
5. 降低训练门槛也降低了滥用门槛；数据许可、隐私、偏见和模型发布责任仍需单独治理。

## QLoRA、RAG 与提示词如何选择

| 问题 | 优先手段 | 原因 |
| --- | --- | --- |
| 任务说明含糊、输出格式不稳定 | 任务契约、提示词、结构化输出 | 先修复输入和验收定义 |
| 需要最新事实、私有资料或可追溯引用 | RAG / 工具调用 | 知识需要更新和引用，不宜固化进参数 |
| 稳定重复的语气、格式、分类或领域行为 | LoRA / QLoRA 候选 | 可以从高质量示例学习行为模式 |
| 工具使用流程经常失败 | 工作流、状态机、权限与恢复 | 微调不能替代系统控制 |
| 还没有独立评测集 | 先建评测 | 否则无法判断微调是否有效或回归 |

只有当任务已稳定、样本可审计、基础方案仍存在重复性差距，而且收益值得训练与维护成本时，才进入 QLoRA 实验。

## 在本机 RTX 4090 24GB 上的最小实验

本机已检测到 NVIDIA GeForce RTX 4090，显存约 24GB。它不适合照搬论文的单卡 65B 实验，但很适合从 7B/8B 级模型开始验证完整方法；13B 级是否可行取决于模型结构、序列长度、批大小、梯度检查点和当前软件实现，应以实际峰值显存为准。

### 实验问题

选择一个稳定且可以评分的任务，例如“把个人知识库检索结果改写为固定格式的学习卡”，不要先做开放式万能助手。

### 四组对照

1. **Base**：基础模型直接回答。
2. **Prompt**：加入稳定任务契约和少量示例。
3. **RAG**：需要库内事实时加入相同检索结果。
4. **QLoRA**：在相同上下文条件下加载适配器。

### 数据与验收

- 先准备 30 到 50 条不参与训练的私有评测题，覆盖正常、边界、拒答和事实不足场景。
- 再整理少量高质量训练样本，记录来源、许可、去重和修订原因；从数百条开始，而不是先追求规模。
- 同时测任务正确性、格式遵守、事实忠实、拒答质量、延迟和峰值显存。
- 模型裁判采用 A/B 双顺序；人工复核全部分歧和严重错误。
- 训练前写清继续、改变和停止条件。若 Prompt 或 RAG 已达到目标，就不因“技术上可以”而微调。

## 与个人知识库主线的连接

- **任务契约**：QLoRA 不能补救模糊目标；训练前必须明确输入、输出、质量和失败方式。
- **评测与信号**：公开基准只用于定位，是否采用适配器由自己的任务集和错误成本决定。
- **最小闭环**：先用一个窄任务跑通数据、训练、加载、评价和回滚，再讨论扩大。
- **决策门槛**：训练前定义最低收益、最大回归、显存预算和停止条件。
- **知识更新**：失败样本应回写到评测集、数据清洗规则和任务协议，而不只是再训练一次。

## 复习卡

1. QLoRA 分别用什么精度存储、计算和更新参数？
2. NF4、双重量化和分页优化器各自减少哪一类显存压力？
3. 为什么“4 位 LoRA 接近 16 位 LoRA”不能改写成“4 位等同全参数微调”？
4. 为什么覆盖全部线性层可能比单独增大 LoRA rank 更重要？
5. OASST1 与 FLAN v2 的结果说明了数据的什么问题？
6. 如何减轻模型裁判的答案顺序偏差？
7. 哪些问题应优先使用 RAG，而不是 QLoRA？
8. 在开始训练前，哪三类基线必须保留？

## 我的最终判断

QLoRA 的长期价值是把“是否值得微调”从大机构的资源问题，转变为更多团队都能验证的工程问题。它最适合解决稳定、重复、可通过示例表达的行为差距。真正决定产品价值的仍是：任务是否明确、数据是否适配、评测是否可信、失败是否可见，以及改进是否超过维护成本。
