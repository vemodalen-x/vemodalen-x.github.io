## 跨文章经营模型

### 1. Product / Market / Distribution 三板

每个实验必须先选一个主板：

- Product：技术可行性、交付质量、用户体验、成本和稳定性。
- Market：具体用户、场景、替代方案、不解决成本、价格和信任。
- Distribution：渠道可达性、流量质量、触达成本、转化和可重复性。

一次只改变一个主变量。若同时换受众、页面、价格和渠道，结果无法归因。

### 2. 分层 MVP 关口

| 关口 | 要回答的问题 | 通过证据 |
| --- | --- | --- |
| Gate 0 技术 POC | 最危险的技术点能否工作 | 可重复 demo、失败条件 |
| Gate 1 人工可交付 | 用户是否愿为结果付款 | 明确价格下的预售或付款 |
| Gate 2 可自助使用 | 陌生用户能否独立完成核心任务 | 激活、完成率、支持请求 |
| Gate 3 可安全收费 | 权限、隐私、支付、异常和退款是否可控 | 安全清单、交付率、退款率 |
| Gate 4 可规模化 | 增量订单是否仍有毛利与稳定质量 | cohort 毛利、留存、支持成本 |

### 3. 信号阶梯

> 曝光 -> 点击 -> 注册 -> 激活 -> 预售/付款 -> 重复使用 -> 留存/复购

前一层不能自动推断后一层：

- 社媒互动说明内容获得响应。
- Product Hunt 排名说明平台发布获得注意。
- 免费注册说明进入产品的摩擦较低。
- 预售说明愿意为承诺付款，同时形成交付责任。
- 重复使用、留存和复购才更接近持续价值。

### 4. 漏斗断点诊断

| 现象 | 优先检查 | 不应立刻得出的结论 |
| --- | --- | --- |
| 没有访问 | 渠道、触达动作、内容分发 | 产品必然无需求 |
| 有访问、无激活 | 受众、承诺、首屏、信任、首个任务 | 只要重做全部功能就会改善 |
| 有激活、无付款 | 价值强度、价格、替代方案、预算主体 | 免费用户多就是成功 |
| 有付款、无留存 | 交付质量、使用频次、支持、期望落差 | 继续扩大买量可以解决 |
| 有留存、增长慢 | 渠道规模、回收期、转介绍、创始人依赖 | 需要立刻增加功能 |

### 5. 预售责任清单

- 明确承诺范围、交付时间和验收标准。
- 公开 beta 状态、限制与第三方依赖。
- 设定最大订单量、排队规则和暂停销售条件。
- 保存退款、返工、缺陷、每单工时和支持量。
- 交付没有稳定前，不因预售成功盲目扩大流量。

### 6. 落地页作为验证工具

1. 写具体用户和发生时刻。
2. 写当前替代方案与不解决成本。
3. 把功能连续追问到最终收益。
4. 添加可核验事实、样例、结果和来源。
5. 处理最关键异议并说清下一步会发生什么。
6. 设置唯一主要 CTA。
7. 用单变量实验和真实转化判断，不用审美偏好决定。

### 7. 双边市场冷启动

- 先选供给侧或需求侧，不同时笼统扩张。
- 解释为什么先突破的一侧会吸引另一侧。
- 设定最小有效密度、匹配时间和区域边界。
- 供给条目数只是库存，匹配、成交、履约和复购才是市场结果。
- 降低每一步入驻摩擦，但不能用无摩擦掩盖价值不足。

### 8. 项目式能力建设

- 只学习完成当前产物所需的最低基础。
- 用两周内可验收的小项目检验理解。
- 指定真实用户或评审人，而不是自己判断“学会了”。
- 技术栈切换设置时间盒，避免学习替代交付。
- 沉淀组件、模板、参考板、失败模式和判断规则。

## 图像证据账本

| 图像类型 | 可以支持 | 不能支持 |
| --- | --- | --- |
| 技术 demo / 原型 | 某项能力在特定环境中曾运行 | 生产稳定、安全、可扩展 |
| 落地页 / UI | 信息与交互结构、当时的承诺 | 需求、转化率、易用性 |
| Product Hunt / 社媒 | 某渠道获得注意或互动 | 用户付费、跨渠道增长 |
| Stripe 首单 / 预售 | 当时出现至少一笔付款信号 | 可持续收入、利润、留存 |
| 注册量 / 流量面板 | 某时间段存在访问或注册 | 激活、付费和用户质量 |
| 学习板 / 渠道图 | 使用了结构化记录与规划 | 执行质量和结果因果 |
| 重构 / bug / 支持图 | 技术与交付负担真实存在 | 全部问题范围与最终质量 |

所有图像条目至少保存：文章、日期、图像类型、支持主张、证明边界、关联实验和下一步证据。不复制原图时，保留原文链接和语义描述即可。

## 对 Business Tutor Agent 的新增规则

1. 经营日志只提炼跨文章重复机制，不把单篇成功故事升级为定律。
2. 独立产品问题自动生成 Product / Market / Distribution 三板和主变量。
3. 快速发布自动检查分层 MVP、安全收费、交付责任和维护债务。
4. 失败复盘自动定位漏斗断点，并列出至少两个替代解释。
5. 落地页问题自动检查用户收益、证据、异议、CTA 和单变量测试。
6. 双边市场自动检查突破侧、最小密度、匹配、履约和复购。
7. 所有公开截图写明它能证明什么、不能证明什么。
8. 预售、付款和留存分层记录，不把虚荣指标升级为价值证据。
