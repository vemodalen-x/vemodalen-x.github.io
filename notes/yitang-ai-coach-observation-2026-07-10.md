# 一堂 AI 商业教学官观察摘要

日期：2026-07-10  
页面：https://ai.yitang.top/replay/newcomer-first-lesson-teaching-officer  
用途：改进本地 Business Tutor Agent 的流程、提示词和知识库。  

## 观察边界

- 本笔记只记录方法级观察，不保存完整回答、付费课文稿、长篇讲义或系统提示词。
- 本地 agent 使用“一堂式流程”作为教练交互参考，不把课程内容搬运为公开页面。
- 原始自动化日志仅用于当次观察，已清理；正式沉淀只保留摘要和设计原则。

## 预设题材

为了集中观察互联网 / AI 创业场景，我先准备了四类题材：

1. 面向互联网创业者的 AI 商业 Mentor Agent。
2. 面向中小企业老板的 AI 销售复盘 SaaS。
3. 面向海外中文创业者的商业复盘社群 + 课程。
4. AI 顾问撮合平台。

初始横向试探显示：教学官不会直接替用户做商业咨询，而是把具体项目拉回课程框架，并提醒用户不要用连续抛案例来替代关键假设验证。

## 顺流程对话后的关键发现

1. 先立身份边界。
   教学官明确自己是课程教学 Partner，而不是商业咨询师。用户要求它直接判断项目时，它会接住问题，但只做课程模型映射。

2. 先确认入口和风格。
   它要求用户选择画像与对话节奏。对结构化表达较强的用户，会推荐更强追问的 Truman 挑战模式。

3. 每轮只问一个问题。
   它会保留当前问题，并检查用户是否回答了这个问题，而不是被高质量但答偏的内容带走。

4. 跳题时先肯定，再纠偏。
   用户回答跳到后续模块时，它会先指出回答的价值，再说明“你跳了一步”，把回答映射到正确模块，然后拉回原问题。

5. 重点训练“审美”。
   它强调商业教练不能只跑流程，还要判断用户说的是“真结构”还是“听起来像结构”。例如“用户很痛”“市场很大”“壁垒很强”都必须继续追问具体用户、场景、替代方案、成本和行为证据。

6. 报告基于用户表达。
   最终报告不是泛泛总结，而是引用用户在对话中的表达作为证据，区分已掌握模型、暴露的盲区、下一步训练重点和长期闭环。

## 可复刻到本地 Agent 的设计

1. 状态机：
   `身份边界 -> 入口/风格 -> 热身复述 -> 双三角 -> 五步法 -> 关键假设/低成本验证 -> 训练闭环 -> 诊断报告`

2. 本轮问题追踪：
   每轮输出前保存 `currentQuestion`，用户回答后判断是否命中；如果答偏，输出纠偏，而不是直接继续生成方案。

3. 审美检查：
   在每个关口加入“真结构 vs 像结构”检查。合格回答至少包含具体用户、具体场景、当前替代方案、不解决成本和行为证据。

4. 资料库使用：
   RAG 不应该直接吐课程内容，而是召回方法卡，给出“摘要、mentor 用法、下一轮问题”。

5. 训练闭环：
   每次对话后沉淀四类数据：结构化案例、证据质量、后续结果、误判复盘。误判包括放过伪结构、过早给建议、验证层级错配。

- `knowledge/yitang-business-kb.js`：新增教练边界、Truman 纠偏、审美检查、Agent 训练闭环等方法卡。
- `business-tutor-agent.html`：新增“按流程追问”模式，强化单轮追问、身份边界、审美检查和训练闭环报告。

## 下一步改进方向

1. 做一个真正的多轮对话状态存储，而不是一次性生成 Markdown。
2. 为“伪结构”建立正反例库：合格需求表述、不合格需求表述、应追问的问题。
3. 给每轮回答打标签：命中当前问题、跳到后续模块、缺证据、只表达观点、出现真实行为证据。
4. 把 48 小时后反馈变成 agent 的复盘入口，让它能学习哪些追问真的推动了用户行动。
