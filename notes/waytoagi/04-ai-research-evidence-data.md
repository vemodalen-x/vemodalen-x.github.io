# AI 研究、论文、报告与数据证据体系

## 研究的目标

研究不是把搜索结果写得更长，而是降低一个具体决策的不确定性。开始前写清：要做什么决定、最关键的未知是什么、哪些证据会改变当前判断、何时停止搜索。

## 证据层级

1. **原始规范与官方资料**：适合确认产品定义、接口、价格、政策原文和厂商自报数据。
2. **原始研究与数据集**：适合检查方法、样本、指标、基线和限制。
3. **独立复现与第三方测评**：用于验证厂商或论文结论能否在不同环境成立。
4. **行业报告与专家分析**：提供结构、市场和解释，但要检查口径、赞助与利益关系。
5. **用户案例与社区经验**：提供真实场景和失败线索，不能直接推出普遍结论。
6. **个人测试**：最贴近自己的任务，但样本小，应明确边界。

目录收录并不代表证据等级相同。涉及关键判断时，至少保留一个原始来源和一个独立来源。

## 论文阅读：主张、证据、限制

### 主张

论文解决什么问题，提出什么新方法，相对哪些基线声称改善，改善的是准确率、速度、成本、安全还是可扩展性。

### 证据

检查数据来源、样本规模、训练与测试泄漏、基线公平性、消融实验、统计波动、硬件和推理预算。只比较最终数字而不看资源投入容易产生错误结论。

### 限制

记录作者明示和未明示的边界：语言、领域、数据分布、上下文长度、真实部署、对抗输入、长期运行和复现成本。

### 决策

阅读后只能进入四种状态：引用、复现、观察、放弃。没有对应行动的论文摘要不必长期积累。

## 行业报告阅读

先看谁发布、为谁服务、数据如何获得、市场口径如何定义。融资额、用户数、访问量、收入和估值是不同指标；同比增长、累计数据和单月数据不能混用。图表应回到原表和时间范围。

可以使用以下提取表：

| 字段 | 内容 |
|---|---|
| 决策问题 | 这份报告帮助判断什么 |
| 关键结论 | 最多三条，使用自己的话 |
| 原始证据 | 数据、样本、访谈或引用 |
| 口径 | 地区、时间、对象和定义 |
| 反例 | 哪些证据削弱结论 |
| 利益关系 | 发布者可能希望读者相信什么 |
| 下一步 | 访谈、测试、继续检索或停止 |

## 产品与市场数据

访问量、下载、注册、活跃、留存、付费和收入分别代表漏斗不同阶段。高访问不能证明产品价值，高融资不能证明商业模式，高增长也可能来自短期渠道。

产品数据应连接动作：找哪些用户访谈、哪个功能形成习惯、哪个渠道只有一次性访问、哪个群体流失。每个指标预先写出上升、下降和无变化时的决策。

## 工具与模型测评

不要用官方演示代替自己的基准。建立真实任务集，固定输入、输出要求和评分量表，比较：正确性、完整性、稳定性、延迟、价格、隐私、工具能力、集成难度和人工修改量。

测评结论要记录日期和版本。模型更新后旧结论是历史证据，不是当前事实。

## 信息冲突处理

1. 不急于求一个统一数字，先检查定义和时间。
2. 区分事实冲突与解释冲突。
3. 优先查看原始资料和方法说明。
4. 将无法解决的冲突写入未知项。
5. 用对决策影响最大的冲突安排下一步调查。

## 最小研究流程

```text
决策问题
→ 当前判断与关键未知
→ 来源计划与停止条件
→ 原始来源优先检索
→ 主张 / 证据 / 限制提取
→ 交叉验证与反例
→ 对个人场景做小测试
→ 写出结论、置信度和下一步
```

## 质量门槛

- 关键事实可回到链接、页码或数据表。
- 事实、来源观点和个人推断分开。
- 快速变化的信息标注核验日期。
- 保留失败结果和反例。
- 明确哪些问题仍未知。
- 结论能改变一个真实决策或实验。
