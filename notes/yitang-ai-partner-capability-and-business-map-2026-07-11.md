## 1. 两个 Partner 的能力分工

| 维度 | 第一课教学官 | 科学决策搭档 |
| --- | --- | --- |
| 核心任务 | 检查用户是否理解课程主干 | 帮用户理清一个真实选择 |
| 主要输入 | 学习印象、复述、疑问 | 决策题目、选项、约束、成本收益 |
| 主要动作 | 提问、补讲、纠偏、学习诊断 | 比较、查漏、找主要矛盾、设去留标准 |
| 典型输出 | 学习证据、盲区、训练建议 | ROI 清单、关键不确定性、决策备忘录 |
| 共同边界 | 不替用户拍板，不伪装知识库外的课程结论，不把口头观点当事实 |

结论：商业 Tutor 不应该只有一种人格。至少需要区分“教学诊断”“业务假设训练”“科学决策”三条流程，再根据用户任务选择状态机。

## 2. 第一课教学官的状态机

`身份边界 -> 用户画像/风格 -> 热身复述 -> 双三角 -> 259/五步法 -> 关键假设/低成本验证 -> 科学体系 -> 学习诊断报告`

关键机制：

1. 一轮只问一个问题，并保存当前问题。
2. 高质量但答偏的内容也要纠偏，不能被漂亮答案带走。
3. 每个关口做“真结构 vs 像结构”检查。
4. 报告引用用户自己的表达作为掌握证据。
5. 它只覆盖第一课，不调用其他课程内容，也不承担项目成败、定价、增长、融资等咨询任务。

## 3. 科学决策搭档的状态机

`明确决策与价值 -> 选择分析深度 -> 逐项收集成本收益 -> 第一版 ROI 对比 -> 用户纠正 -> AI 查漏 -> 高度扫描 -> 主要矛盾 -> 停止/继续/加注 -> 决策备忘录`

### 3.1 四种分析深度

1. 简单拆拆：把选项的成本收益列清楚。
2. 主要矛盾：找到真正改变选择的冲突和不确定性。
3. 公式定量：把关键变量写成区间和计算关系。
4. 完整财务账：比较乐观、基准、悲观情景。

启发：先对齐深度，防止简单问题过度建模，也防止高代价决策只做表面罗列。证据不足时，区间比虚假的精确数字更诚实。

### 3.2 多方案 ROI 画布

每个方案至少比较：

- 直接收益与长期收益。
- 现金成本、时间成本、注意力和信誉成本。
- 风险与不确定项。
- 可逆性与退出代价。
- 学习速度和可沉淀资产。
- 对其他方案的贡献。

重要修正：多个方案未必互斥。内容、人工服务、软件产品常常分别承担获客、验证和规模化，应先判断真实问题是“三选一”还是“先后顺序”。

### 3.3 高度扫描

1. 长期复利：验证结束后，哪些资产仍会产生价值？
2. 可逆性：四周后信号不好，掉头代价多大？
3. 机会成本：同样资源的最强替代用途是什么？
4. 时间窗口：优势来自市场变化，还是个人当前的知识、资产和行动势能？

这个扫描能防止两类误判：用“风口”合理化重投入，以及只算现金、不算时间和注意力。

### 3.4 决策的完成标准

决策报告不应只给结论，还要提前写清：

- 样本量、期限和预算。
- 哪些证据出现时停止。
- 哪些真实行为支持继续。
- 哪些条件同时成立才允许加注。
- 到期后的强制复盘日期。

行为证据优先级通常高于口头认可：付费、行动闭环、复访、复购和转介绍都比“听起来不错”更可靠。

## 4. 商业 Tutor 项目的实战推导

当前三个方向可以重新写成一个顺序，而不是三选一：

1. 先用“人工 + AI 陪练”验证付费场景、拒绝原因和结果价值。
2. 把有效追问、证据标准、会前问卷和会后复盘沉淀为工作台。
3. 只做必要的原创内容承担信任与获客，不把课程摘要当核心商品。

建议验证门槛：

- 定向触达 30 个目标用户，完成至少 10 次需求或演示对话。
- 获得至少 3 个付费试点。
- 至少 2 个用户完成“问题 -> 假设 -> 行动 -> 复盘”闭环。
- 出现复购或转介绍意愿，才考虑扩大产品开发。
- 若达到样本量后无人付费，或付费后无法推动行动，停止当前定位并复盘。

时间边界：每周投入控制在 8-10 小时；真人陪练每周最多 2 次；匿名化案例、评测方法和工作台同时转化为求职作品集，避免挤压现金流和职业主线。

## 5. 最值得继续学习的商业知识

### 第一优先：需求验证与用户研究

要解决的问题：什么任务场景足够高风险、临近决策，能触发真实付费？用户为什么拒付？

应沉淀的产物：用户原话库、替代方案、拒付原因、行为证据、需求关口通过标准。

### 第二优先：行业常识与情报调研

要解决的问题：哪些结论可以通过行业常识、竞品、客户、渠道、供应链和监管信息先查清，不必用产品实验重做一遍？

应沉淀的产物：行业基准、竞争地图、证据来源、事实与假设分栏。

### 第三优先：商业模式与单位经济性

要解决的问题：谁付钱、为什么付、交付毛利如何、销售与回款周期多长、人工和模型成本能否被价格覆盖？

应沉淀的产物：收入结构、成本结构、毛利、交付时长、LTV/CAC、回本周期和情景区间。

### 第四优先：分发、销售与增长引擎

要解决的问题：没有稳定客户时，如何触达首批 5-10 个目标用户？价值成立后，哪条渠道能重复获得相似客户？

应沉淀的产物：目标名单、触达话术、演示转化、销售周期、复购与转介绍路径。

### 第五优先：产品设计与 AI 交付

要解决的问题：人工验证过的流程里，哪些步骤适合产品化，哪些必须保留人类判断？

应沉淀的产物：状态机、证据标签、提示词评测、隐私边界、失败转人工条件和服务 SOP。

### 第六优先：团队、财务、法务与融资

这些是从“能卖”走向“可持续”的后续能力：团队分工和激励、现金流与预算、合同和知识产权、数据合规、融资时机和资本成本。它们不应早于需求与单位经济性验证，但不能在规模化前缺席。

## 6. 对本地 Agent 的新增要求

1. 先做任务路由：教学、业务假设、真实决策。
2. 决策模式必须让用户选择分析深度。
3. 多方案逐项收集，AI 补充项与用户事实分开显示。
4. 报告加入长期复利、可逆性、机会成本和时间窗口。
5. 每份报告必须有停止、继续、加注和复盘日期。
6. 把“学习速度”加入早期项目收益，不只看短期收入。
7. 区分市场窗口和个人窗口，禁止用紧迫感替代证据。

## 7. 本次观察的产品边界

- Partner 强制开启对应课程知识库，用户不能关闭。
- 第一课教学官只覆盖第一课，无法替代一堂全部课程的 RAG。
- 科学决策搭档可以处理真实选择，但不会直接给最终答案。
- 页面偶发请求无响应，缺少清晰的错误恢复和断点续问提示；本地 Agent 应保存会话状态、待回答问题和最后成功里程碑。
- 页面会显示模型思考过程；本地资料库不保留、不复刻这些内容。
