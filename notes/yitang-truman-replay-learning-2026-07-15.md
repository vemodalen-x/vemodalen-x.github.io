## 二、实测主线

完整测试观察到以下功能阶段：

1. **复盘契约**：说明身份、预计时长、私下复盘定位和最终交付，再要求用户明确回复“开始”。
2. **起心动念**：不先拆功能，先问项目最早认为非做不可的动作。
3. **真实使用瞬间**：把抽象用户需求压到压力、选项、时间限制和期望输出。
4. **事实镜像**：并置“投入最多的动作”和“最想服务的时刻”，提出错位假设。
5. **偏差确认**：让用户自己命名虚假进度或判断偏差，教练不替用户盖棺定论。
6. **长期后果**：把偏差投射到三年后，形成维持现状的成本。
7. **体系映射**：把用户表达接回科学决策、五步法、假设验证和复盘数据结构。
8. **直接阻力**：从知道该做什么，追到最具体的执行卡点。
9. **最小体检**：把首次服务压成 30 分钟、四步、低负担的决策体验。
10. **行动承诺**：确认第一个对象、动作和具体截止时间。
11. **结果回传**：要求一句极短的回传指令，把一次咨询变成未完成实验。
12. **总结信**：复述已确认偏差、真实引擎、行动和课程价值主张。

这 12 个功能阶段与公开描述中的“12 步故事线”数量一致，但名称来自行为归纳，不等于原始框架文件的正式标题。

## 三、最值得产品化的机制

### 1. 场景镜像，不从功能开始

先问“你最早做了什么”，再问“用户真正会在什么时刻打开它”。两段用户原话并置后，偏差变得可见。本次测试的核心校准是：知识库是证据底座，不是用户面对的主要产品；真正的产品是从混乱叙述到可验证行动的决策能力。

### 2. 30 分钟创业决策专项体检

| 步骤 | 输入 | 产出 |
| --- | --- | --- |
| 目标与障碍 | 本周期目标；当前最大障碍 | 可操作问题 |
| 路径与理由 | 2-3 条候选路径；各自成功理由 | 显性假设 |
| 最危险假设 | 前置性、影响、证据缺口、验证成本 | 单一优先假设 |
| 最小实验 | 几天内、低成本、可证伪 | 行动、判据、回访日 |

只问“错了是否致命”还不够。本地实现增加了证据缺口和验证成本，避免把主观恐惧误当优先级。假门、广告和预售实验必须额外检查知情、品牌、退款、合规与交付风险。

### 3. 结果回传是产品引擎

第一次会话固定记录：`target`、`owner`、`deadline`、`experiment`、`success_signal`、`failure_signal`、`return_date`、`status`。状态必须区分演练、计划、已发出、已执行和已复盘。本次对话中的对象 A 与期限只是演练，没有被标成真实发送。

真正的数据飞轮应是：真实问题 -> 关键假设 -> 验证动作 -> 用户带回结果 -> 更新原判断 -> 沉淀误判规则。内容数量和即时满意度都不是核心飞轮。

### 4. 运行时控制与知识 DataPack 分离

可迁移架构是：

- Runtime Prompt 只管当前状态、允许的转移、一轮一问、偏题处理、结束条件和安全边界。
- DataPack 只提供课程方法、案例、术语、语气素材和证据卡，不改变流程状态。
- Retrieval 只返回支持当前关口的最少卡片，不把整套课程塞进每轮回复。
- Session Ledger 保存用户事实、Agent 推断、待验证假设、当前问题和待处理分支。

## 四、不能直接照搬的部分

1. **过度肯定**：多轮用长篇赞美制造确定感。改进为最多两句，只肯定透明度、具体性或已完成行动。
2. **修辞替代证据**：火场、雷管、引擎等比喻有记忆点，但不能升级为因果结论。
3. **最坏情形放大焦虑**：必须补最早预警指标、可逆动作和替代解释。
4. **过早销售转场**：课程价值铺垫出现在外部验证之前。商业推荐必须与诊断分区、披露利益关系，并允许用户跳过。
5. **身份升级**：总结信把用户描述成“科学家型创业者”等身份。改进为只复述事实、候选偏差、行动和未决问题。
6. **实验伦理缺口**：假门测试可能伤害信任。必须写明不误导承诺、退款与数据边界。

## 五、Business Tutor 已采用的规则

- Truman 模式改为显式复盘状态机，不再只是“更尖锐地追问”。
- 新增场景镜像、30 分钟体检、结果回传和质量护栏 RAG 卡。
- 下一问按用户文本所处关口选择，并维持一次只问一个问题。
- 最坏情形必须带预警指标；行动必须带真实状态；总结信禁止身份锁定。
- 课程推荐与诊断证据分开，不把课程映射当效果证明。

## 六、建议监控的产品指标

| 层级 | 指标 |
| --- | --- |
| 流程质量 | 一轮一问遵守率、跳题拉回成功率、到达关键假设的中位轮次 |
| 诊断质量 | 事实/假设区分完整率、危险假设被用户确认或修正的比例 |
| 行动质量 | 有对象与期限的承诺率、实验判据完整率、按期执行率 |
| 学习闭环 | 3/7 日回传率、原判断更新率、误判规则沉淀率 |
| 商业价值 | 第二次带真实问题回来率、付费转化、长期留存、转介绍 |
| 安全与信任 | 敏感信息最小化、过度确定投诉、商业推荐跳过率、实验伦理事件 |

## 七、结论

Truman Partner 最值得学习的不是 CEO 口吻，而是稳定主线、具体场景镜像、逐步承诺和结果回传。Business Tutor 的核心不应继续扩大内容表面积，而应优先验证：它能否在真实决策中更快找出关键假设、促成可执行实验，并在回访时根据结果修正原判断。
