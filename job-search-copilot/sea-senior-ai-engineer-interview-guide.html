1 · 60-second introduction

Hi, I’m Junxian. I’m a Senior AI Engineer based in Singapore, with close to four years of experience taking AI features from model development into production systems. At Black Sesame Technologies, I work on real-time computer vision products, including portrait segmentation and matting, depth-aware rendering, and model-to-device delivery across C++, Android, evaluation, and on-device debugging. A key part of my role is turning field failures into reproducible hard cases and coordinating release decisions across product, runtime, tuning, and QA teams. I also use AI-assisted engineering workflows for suitable internal tasks to make experiment setup, training iteration, test-case generation, and regression analysis faster and more repeatable. The important part is that production changes still go through clear acceptance criteria, human review, and release gates. I’m now looking to apply that production discipline to agentic enterprise products, which is why this Sea opportunity is especially relevant to me.

2 · Why Sea / why this role

I’m interested in this role because it combines product ownership with the engineering depth needed to make agentic AI reliable in production. The job description covers multi-step reasoning, tool calling, memory, orchestration, evaluation, latency, cost, and governance as one end-to-end problem. That matches how I like to work: start from a product requirement, define measurable acceptance criteria, build the runtime path, and own the feedback loop after release. Sea also offers the scale and cross-functional environment where those reliability and governance decisions matter in practice.

3 · Why are you considering a move?

I’ve built a strong foundation in production computer vision and edge AI, and I’m proud of the systems and delivery discipline I’ve developed there. My next step is to work closer to agentic products where model behaviour, tools, state, evaluation, and user workflows need to be designed together. I’m not moving away from production engineering; I’m looking to apply it to a broader AI product problem with greater end-to-end ownership.

4 · LLM / Agent experience boundary

My strongest production track record is in computer vision and edge AI. I use AI-assisted engineering and agent-style workflows within project work to accelerate repetitive design, experiment, training, and validation tasks, but I would not describe that as two years of enterprise LLM production ownership. What transfers directly is the production discipline: explicit contracts, observability, hard-case evaluation, human review, staged release, rollback, and cost-quality trade-offs. I’m confident in the transfer, and I’m happy to demonstrate it through an end-to-end agent design.

Priority question bank

岗位定向题库

先口述结构，再补细节。每题至少包含一个失败模式或权衡。

1. 什么时候应该使用 deterministic workflow，什么时候使用 agent？
对应：G11。先按任务可分解性、路径稳定性、错误成本和反馈可得性判断；固定流程优先 workflow，开放环境与动态决策才使用 agent。最后讲 agent 增加延迟、成本与不可预测性，并设计最大步数、终止和人工升级。
2. 为 Sea 的企业生产力产品设计一个能执行任务的 AI Copilot。
对应：S3 / G10–G14。回答顺序：用户与成功标准 → 不可自动化边界 → planner/executor/tools/memory → RBAC/tenant/audit → eval/trace/fallback → SLO/成本 → 灰度与回滚。不要从框架名开始。
3. 如何设计安全、可重试且有副作用的 tool calling？
对应：G12。typed schema、权限最小化、read/write 分级、确认点、idempotency key、timeout、bounded retry、compensation、审计与 dry-run；外部返回值视为不可信数据。
4. Agent memory 应该存什么，何时写，怎样防止污染？
对应：G11/G13。区分 thread state、semantic、episodic、procedural memory；默认用户命名空间；共享 policy 只读；写入要经过抽取、去重、TTL/版本与敏感信息过滤，高风险写入人工确认。
5. 单 Agent 与 Multi-Agent 如何选择？
对应：G11。先用单 agent + typed tools 建 baseline；只有角色需要不同上下文、工具权限或可并行子任务且收益被 eval 证明时再拆分。明确 handoff、共享状态、重复工作、死循环和成本放大风险。
6. 完整设计一个企业 RAG pipeline。
对应：G6。数据权限与版本 → parsing/chunking → sparse+dense → metadata/tenant filter → rerank → context packing → citation → generation/abstention → cache/refresh → offline/online eval。
7. 如何分别评估 retrieval、generation 与 agent trajectory？
对应：G7/G14。Retrieval：recall@k、MRR/nDCG、权限泄漏；Generation：faithfulness、answer relevance、citation、abstention；Agent：task success、tool/arg accuracy、step efficiency、recovery、termination、human escalation、latency/cost。
8. Prompt、RAG、Long Context、Fine-tuning 和 Tool Calling 怎么选？
对应：G5。先说问题类型：接口/格式用 prompt 或 constrained output；新鲜/私有事实用 RAG；确定性计算或行动用 tool；稳定行为差距且数据充足才 fine-tune。所有路线用同一私有 eval 对比。
9. 如何防 prompt injection、越权与 PII 泄漏？
对应：G13。指令与外部内容分层、工具 allowlist、参数验证、least privilege、tenant filter、敏感动作确认、输出/日志脱敏、red-team 与不可绕过的 policy gate；不能只说 system prompt。
10. 线上没有即时 ground truth，怎样监控 Agent 质量？
对应：S7。代理信号 + delayed labels +抽样人工审查；监控任务完成、重试/循环、工具失败、人工接管、p95 latency、cost、异常输入、版本与 drift；保留可回放 trace，不能把“没有报错”当成功。
11. 怎样做模型 / prompt / retrieval 版本发布和回滚？
对应：S6。immutable artifact、config/version、golden set、shadow、canary、acceptance gate、kill switch、回滚与审计。用 Model-to-Device 交付工作流作为真实类比。
12. 如何优化 Agent 的 latency、cost 与 accuracy？
对应：S8/G10。拆 prefill/decode/tool/retrieval latency；模型路由、缓存、并行只用于独立步骤、上下文压缩、预算和早停；报告 cost per successful task，而非只报 token 单价。
13. VEMO 如何证明治理规则真正生效？
结构：问题是 prose-only rule 可被忽略 → 用 hook、Git gate、CI 三环强制 → risk tier 与 capability tier 决定 ceremony → independent judge 处理高风险 → conformance eval 验证 gate 会触发。最后讲它仍需按企业身份、数据与部署环境定制。
14. BFS / 最少硬币 / Top-K 最大数。
面经关联：Shopee 算法面经出现 BFS、coin change 与维护 N 个最大数。练习协议：先澄清输入 → baseline → 最优复杂度 → 边界测试 → 口述内存与大规模变体。
15. 实现 LRU cache，并讨论线程安全。
对应：C7。hash map + doubly linked list，O(1) get/put；补容量 0、更新、eviction、并发锁粒度、sharding 与持久化边界。
16. 设计 API rate limiter。
Sea 相邻 SWE 面经：从 fixed/sliding window、token bucket / leaky bucket 比较；再追问分布式状态、一致性、热点 key、内存、时钟、并发与降级。
17. AUC 如何从排序后的正负样本计算？
面经关联：Shopee MLE 面经出现。解释 pairwise 概率、rank-sum 公式、ties、O(n) 扫描与类别不平衡下 AUC 的边界；再连接 PR-AUC 与业务成本。
18. 讲一次离线指标好、上设备却失败的案例。
对应：R4。明确数据分布、pre/post-processing、runtime、状态切换或视觉主观指标哪一层出错；讲你怎样建立可复现样例、逐层 parity 与发布门槛。
19. 讲一次跨团队分歧，你如何形成可验证的决策？
对应：B2/B5。不要只说“沟通”。说明各方目标、你建立的共同数据/验收标准、弃选方案、决策 owner 与结果。
20. 为什么 Sea Corporate Lab，为什么现在？
连接三点：企业工具向可执行智能助手演进；你能带来生产 AI、runtime、eval 与交付纪律；希望把可运行的 agent governance 经验推进到更真实的企业场景。可提 Sea 2026 AI CoE 与 AI 合作信号，但不要假设本岗位直接隶属这些项目。
21. 你需要工作签证支持吗？
简洁真实："Yes, I will require employment visa sponsorship for this role. I am currently based in Singapore and can provide the necessary documents promptly." 不主动展开政策判断，也不回避。
