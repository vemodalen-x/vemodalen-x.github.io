# Learning OS V3：让“能力证据”经得起延迟检验

当前入口：[打开 Interview Learning OS V3](learning-os.html)。V2 评审保留在 [learning-experience-v2.md](learning-experience-v2.md)，用于追踪设计演进。

## 这一版修复什么

V2 已经建立能力图、可解释推荐、六步 Session、分层提示和五维评分，但真实使用后仍有四个会扭曲学习判断的结构性问题：

1. 同一 Session 内刚做完的迁移题被计入 Unaided Transfer Success，混淆了即时表现与延迟保持。
2. 五维评分默认选择 3，容易产生锚定偏差和“无意中通过”。
3. 队列显示固定数量节点，没有真正服从 30/45/60/90 分钟的当天预算。
4. 关闭 Session 会丢失作答，长任务的恢复成本过高。

V3 不继续堆题，而是提高证据的效度、可解释性和可持续使用性。

## 1. 延迟无辅助复测才是北极星

V3 将证据分成两类：

- **即时练习**：同一 Session 内完成 Retrieve、Construct、Challenge 和 Exit Ticket，只形成“候选证据”。
- **延迟复测**：节点到期后，不展示历史答案，加入新的约束变式重新作答。

只有同时满足以下条件才计入 Unaided Transfer Success：

- 节点已经到期，属于 delayed review；
- 本次未使用任何提示；
- Transfer ≥ 3；
- Independence ≥ 3。

原有 V2 历史记录会被保留，但不会被追溯性地包装成延迟复测。这样指标会暂时变得更低、更稀疏，却更诚实。

### 复测变式

系统在五类变式中轮换，避免只复现原题：

- 约束反转；
- 最小反例；
- 规模迁移；
- 故障注入；
- 角色切换。

它们仍是透明启发式，不等于自动生成并验证了高质量等价题。真实使用中应检查变式是否保持目标能力、难度是否接近。

## 2. 评分不再默认通过

Correctness、Reasoning、Transfer、Communication、Independence 五个维度都从空白开始，必须主动选择 0–4 的证据锚点。例如：

- Transfer 3：新约束下结论仍成立；
- Independence 3：无提示完成；
- Reasoning 4：能用反例比较替代方案。

进入 Exit Ticket 前，还必须写下最大的一个误差和最小修复动作。系统不把空白当 0，也不会默认填 3。

这仍然是自评，不是可靠自动评分。建议每周至少用一次同伴、mentor 或严格 AI evaluator 对同一证据独立打分，计算评分差异。

## 3. 从“下一批题”改成预算化任务包

系统根据当天 30/45/60/90 分钟预算构造最多四个 Session：

- 已到期的延迟复测先进入硬优先层，避免新题长期挤占检索复习；
- 到期复测通常缩短为原任务时长的约 55%，但保留闭卷、变式和评分；
- 新节点使用完整预计时长；
- 第一项超过预算时自动变成当日 sprint，不把超时任务伪装成可完成计划；
- 页面明确显示计划使用分钟数和剩余预算。

当前使用贪心启发式，不保证全局最优组合。更重要的验证指标不是“预算装得多满”，而是任务包是否能按时完成，以及延迟迁移是否改善。

## 4. 草稿恢复与状态迁移

Session 中的文本、信心、评分、提示层级、阶段和有效练习时长会自动保存在浏览器。关闭弹窗或页面后，可以从恢复条继续；暂停时间不计入练习时长。

状态版本升级为 V3，并自动读取旧的 `interview-learning-os-v2` 本地状态。导入 V2 JSON 时：

- 节点掌握度与证据保留；
- 旧证据标记为即时练习；
- 不虚构 delayed review 或 unaided transfer；
- 新字段使用保守默认值。

## 5. 桌面入口、聚类目录与离线检索

桌面版不改变学习证据模型，而是在同一份本地应用上增加三个发现入口：

- Windows 快捷方式以 Chrome/Edge App 模式打开本地页面，形成无地址栏的独立窗口；`launch-learning-os.cmd` 是可移植的回退入口。
- 目录先用 P1–P8 第一性原理标记文档、章节与练习，再与 K1–K8/META 交叉筛选；同一知识可以服务多个原语和能力簇，不复制正文。
- 构建脚本把仓库内 28 份 Markdown 拆成 646 个章节索引；搜索同时覆盖章节全文与 70 个多标签 TASKS 中的目标、问题、迁移、提示和 rubric。

`knowledge-index.js` 是生成物，不是真源。真源仍是各 Markdown 和 `learning-os.js`；每次修改知识文件后必须重新运行 `node scripts/build-knowledge-index.cjs`。生成器要求每份 Markdown 都有显式元数据，新增文件没有进入目录时构建会失败，而不是静默遗漏。

搜索只负责发现与定位，不把关键词命中当作掌握证据。点击练习结果会进入原有六阶段 Session；点击知识章节只进入阅读器，不增加 mastery、完成量或北极星指标。

## V3 数据契约

每条新证据增加：

- `sessionMode`：`learn` 或 `review`；
- `isDelayedReview`：是否为到期后的延迟复测；
- `reviewLagDays`：相对到期日延迟多少天；
- `variant`：本次约束变式；
- `unaidedTransfer`：是否满足零提示与双门槛；
- `durationSeconds`：扣除暂停后的有效 Session 时长。

草稿保存在 `state.draft`，完成 Session 后立即清除。单个回答最多保存 6000 字符，最近证据保留 100 条，以降低浏览器 localStorage 超限风险。

## 验证标准

V3 发布前至少验证：

1. V2 状态能迁移，旧记录不计入延迟北极星。
2. 30/45/60/90 分钟均生成不超预算的任务包。
3. 五维评分未选完整时不能进入 Exit Ticket。
4. 关闭并重开页面后，草稿、阶段、提示和计时可恢复。
5. 普通即时 Session 完成后不增加北极星分母。
6. 到期复测只有在零提示且 Transfer / Independence ≥ 3 时通过。
7. 导出再导入后，上述状态保持一致。
8. 知识索引覆盖仓库内每一份 Markdown，且来源数、章节数与生成器输出一致。
9. P1–P8 与 K1–K8/META 可以单独或组合筛选；资料目录、关键词检索和章节阅读器可以在 `file://` 离线环境工作。
10. 搜索结果能同时打开知识章节和对应练习 Session，但阅读不会伪造学习证据。
11. 桌面快捷方式指向日常使用目录，应用更新后仍能读取原有本地状态。

## 仍然没有解决的差距

- P×K 标签是人工维护的检索坐标，不是掌握证据；文档级 P 标签偏宽，只有通过陌生题闭卷作答与延迟迁移复测，才能验证某个原语是否真的可迁移。
- 70 个节点是核心训练集，其中包含 7 个 Agent/FDE 主干节点、9 个 2026 FDE 求职/编码/企业交付节点、3 个 Kimi K3 架构/Agent 训练/Serving 节点、2 个 SenseNova-U1 统一多模态节点、3 个 Smol Course 后训练/VLM 节点、2 个 Vincent Sitzmann 前沿 CV 节点、5 个《深入理解 AI Agent》节点、2 个 Hello-Agents 实现/项目节点、3 个 Harness Engineering 节点、1 个 Harness 播客听辨节点、2 个 Topcoder Fullstack 节点、2 个分布式复制/幂等节点和 2 个 Prompt 契约/评测节点；230 道 FDE 问题作为检索型扩展题库，具体 JD 仍需定向激活而非全部顺序学习。
- 没有运行代码测试、解析口述或自动核验架构图；评分依然需要外部校准。
- 复测变式是规则模板，没有经过难度等值实验。
- 推荐权重和复习间隔没有个人真实数据验证。
- 没有同伴评审、mentor dashboard 或匿名 benchmark。
- 当前搜索是本地关键词相关性 baseline，没有 embedding、同义词词典或查询质量标注；它适合定位，不保证语义召回完整。
- 没有证明 V3 比 V2 提高了真实面试表现。

## 下一轮实验

连续使用 14 天，至少形成 12 次即时练习和 6 次延迟复测。每次记录是否按预算结束、提示层级、五维分数和自信度；第 14 天再做一场随机 mock。只有当延迟无辅助迁移、校准误差和 mock 评分同时改善，才考虑加入语音、代码运行或 AI evaluator。否则先修任务难度、评分锚点和复习间隔。
