# 《深入理解 AI Agent》面试化学习路线

资料：李博杰《深入理解 AI Agent：设计原理与工程实践》，中文 PDF v1.2，2026-07-23，共 307 个 PDF 页面。配套实验代码见 [bojieli/ai-agent-book](https://github.com/bojieli/ai-agent-book)。

这份路线不要求从第 1 页顺序读到第 307 页。目标是把书中的架构原则转成面试时可以闭卷解释、画图、设计、诊断和验证的能力证据。

配套路线：[Harness Engineering 面试化学习路线](harness-engineering-plan.md)负责 Coding Agent 的仓库工程环境。AID-1/2/4 讨论运行时 Harness，AID-5 建立搜索-编辑-验证闭环，随后 HE-1/3/6 把仓库地图、机械约束、反馈与行为正确性接入闭环，避免重复学习“Harness”一词。

## 先明确边界

- PDF 是学习来源，不复制进 Git；仓库只保存学习路线、题目和自己的证据。
- 书中的产品名、模型版本和生态判断会变化；优先学习穿越版本的架构原则，并用官方文档或实验验证具体实现。
- “看完一章”不算完成。每个 Session 必须留下图、代码、trace、评估表或口述记录。
- 同一 Session 内答对只形成候选证据；到期后零提示换约束复测，才计入 Learning OS 的延迟无辅助迁移。

## 8 个核心 Session

每次先闭卷 8-10 分钟，再定向阅读 15-25 分钟，最后完成输出和迁移。页码使用 PDF 正文印刷页码；PDF 查看器页码通常比正文页码多 8 页。

### AID-1 · Agent 循环与 Harness 边界

- **阅读**：第 1 章 pp.7-26，重点 1.1.4、1.2。
- **闭卷问题**：为什么 Agent 不能只定义为“会调用工具的 LLM”？静态前缀、运行轨迹、循环控制和验证分别由谁负责？
- **输出**：画出 `LLM -> action -> tool/environment -> observation -> LLM`，旁边标出 Harness 的模型访问、上下文组装、工具执行、循环控制和验证职责。
- **迁移**：把任务改成严格合规的付款操作；哪些步骤必须从模型决策移到确定性控制面？
- **过关**：能解释 workflow 与 autonomy 是连续谱，不用框架名称代替架构判断。

### AID-2 · 上下文预算、缓存与压缩

- **阅读**：第 2 章 pp.27-68，重点 2.2、2.3、2.6、2.7。
- **闭卷问题**：区分系统/工具静态前缀、用户输入、模型响应、工具结果、状态栏和历史轨迹；它们为何不能随意重排？
- **输出**：做一张 context budget 表，列 token、变化频率、可信边界、缓存影响、淘汰/压缩策略和恢复来源。
- **最小实验**：固定模型与请求，比较稳定前缀、每轮改时间戳、分层压缩三种方案的首 token 延迟与输入 token。
- **迁移**：任务跨会话续跑且审计轨迹不能丢；设计“可恢复状态”而不是只保存摘要。
- **过关**：能同时讨论正确性、KV/Prompt Cache、信息损失和注入风险。

### AID-3 · 记忆、RAG 与知识治理

- **阅读**：第 3 章 pp.70-99。
- **闭卷问题**：用户偏好、一次性会话事实、组织知识和可执行规则分别应该放在哪里？
- **输出**：画出写入、整理、检索、引用、更新、删除和审计链；明确 dense/sparse/hybrid、metadata、rerank 与 abstention。
- **迁移**：用户撤回一个偏好且知识库文档过期；如何防止旧信息继续通过缓存、摘要或索引生效？
- **过关**：不把长期记忆等同于向量库；能说明时效、隐私、来源和冲突解决。

### AID-4 · 工具 contract、安全与异步事件

- **阅读**：第 4 章 pp.100-127。
- **闭卷问题**：感知、执行、协作、事件触发、用户沟通五类工具的调用方向、失败成本和权限为何不同？
- **输出**：为“发送邮件”写完整 contract：schema、权限、确认、幂等、timeout、重试、补偿、审计和人工升级。
- **迁移**：Agent 执行中收到用户取消，同时下游服务超时后返回成功；给出状态机和一致性策略。
- **过关**：模型只提出动作，控制面决定动作是否被授权和执行；异步中断不会造成重复副作用。

### AID-5 · Coding Agent 的搜索-编辑-验证闭环

- **阅读**：第 5 章 pp.128-158。
- **闭卷问题**：为什么“生成一段代码”远弱于 Coding Agent？文件系统、搜索、编辑、执行和测试如何形成可恢复轨迹？
- **输出**：给一个真实小仓库任务，记录搜索依据、最小 patch、测试、失败恢复和停止条件；不要只保存最终 diff。
- **迁移**：两个 Agent 同时修改共享文件且一个测试失败；设计所有权、冲突检测、回滚和交接协议。
- **过关**：能用失败恢复、权限与验证说明 Harness 的价值，而不是只谈模型编码能力。

### AID-6 · 可重复的 Agent 评估

- **阅读**：第 6 章 pp.159-186。
- **闭卷问题**：如何区分模型能力不足、工具设计缺陷、上下文缺失和循环控制错误？
- **输出**：建立 eval matrix：环境、任务分布、ground truth/verifier、端到端成功、step/trace、工具参数、终止、人工升级、延迟、成本和安全。
- **对照实验**：固定 Harness 换模型；再固定模型逐一消融检索、提示、工具或反馈。提前定义接受门槛和置信区间。
- **迁移**：LLM judge 与人工在高风险 slice 上系统性分歧；设计校准、抽检和上线阻断策略。
- **过关**：评估结果能路由到具体系统改动，不只是生成一个总分。

### AID-7 · 多 Agent 何时值得

- **阅读**：第 10 章 pp.266-296，重点 10.1-10.5。
- **闭卷问题**：什么时候多 Agent 的隔离、并行或专业化收益能覆盖通信、协调、上下文重复和错误级联成本？
- **输出**：用同一任务比较单 Agent、共享上下文角色转换、管理者模式和独立上下文协作；标出消息契约与终止条件。
- **迁移**：并行子任务共享文件系统且上游事实错误；设计冲突检测、证据引用、独立验证和故障域。
- **过关**：默认先给单 Agent baseline；不能证明可分解性或独立验证收益时，不增加 Agent 数量。

### AID-8 · Capstone：生产级研究与执行 Agent

- **阅读**：只回查前七个 Session 的失分段落，不再泛读。
- **任务**：设计一个能检索内部知识、运行代码、生成报告并请求发布批准的 Agent。
- **必须包含**：目标/SLO、控制面与模型面、上下文预算、记忆/知识、工具 contract、异步恢复、注入防护、trace schema、eval set、模型路由、成本、canary、rollback 和人工升级。
- **故障注入**：过期文档、恶意检索内容、工具部分成功、模型超时、重复事件、上下文压缩丢失关键约束。
- **证据**：一张架构图、一张状态机、一张 eval matrix、三条失败 trace 和 12 分钟讲解录音。
- **过关**：45 分钟内完成设计；D+7 随机注入新故障时仍能零提示修订。

## 3 个岗位选修

### AID-X1 · 后训练

阅读第 7 章 pp.187-225。用一个工具调用任务比较 SFT、RL 和 Harness 修复：什么改变行为分布，奖励怎样验证，过程奖励与结果奖励各有什么泄漏或投机风险。只在模型训练/RL JD 中纳入六周主线。

### AID-X2 · 自我进化

阅读第 8 章 pp.226-239。设计“失败 -> 可验证经验 -> Skill/工具候选 -> 沙箱评估 -> 人工批准 -> 版本化发布 -> 回滚”，明确 Agent 不能自行扩大权限。平台、Agent infra 或研究岗使用。

### AID-X3 · 多模态与实时交互

阅读第 9 章 pp.240-264。比较 cascading、omni、full-duplex 三种语音架构，以及 Computer Use / VLA 的感知-动作延迟、grounding、打断和 Sim2Real 风险。语音、VLM、机器人或端侧多模态岗使用。

## 复测题池

1. 去掉历史轨迹、工具定义、工具结果或思考/决策过程之一，Agent 会出现什么可观察失败？如何做消融验证？
2. 每轮注入当前时间为何可能让缓存成本突然上升？如何保留时间感知又减少稳定前缀失效？
3. 记忆、RAG、长上下文、Skill 和工具各解决什么问题？给一个选择错位的反例。
4. 工具执行“超时但实际成功”时，为什么普通 retry 危险？幂等键、查询状态和补偿如何配合？
5. 最终答案正确但轨迹包含越权调用，评估应该判多少？端到端与过程指标如何组合？
6. 强模型分数更高但成本和尾延迟翻倍；需要哪些 slice、置信区间和产品门槛才能决定替换？
7. 什么时候子 Agent 的上下文隔离优于压缩主 Agent 上下文？它会引入什么信息损失？
8. 多 Agent 并行后成功率下降，如何区分任务不可分、消息契约丢信息、并发冲突和错误级联？
9. Agent 从失败中生成新 Skill，怎样避免把一次偶然 workaround 固化为长期能力？
10. 语音或 Computer Use Agent 的实时性问题，为什么不能只靠更快模型解决？

## 完成定义

- AID-1、2、4、6、7 至少各完成一次即时练习和一次 D+1/D+3 延迟复测。
- AID-5 留下真实可检查的搜索、编辑、测试和恢复轨迹。
- AID-8 在随机故障注入下达到 Correctness、Reasoning、Transfer、Communication、Independence 均至少 3/4。
- 能把书中的原则连接到自己的项目证据；没有真实证据的部分明确标为设计能力或学习方向。
