# Learning OS V2：从静态备考表到自适应学习系统

> 此文档保留为历史设计记录。当前版本与证据有效性修正见 [Learning OS V3](learning-experience-v3.md)。

配套原型：[打开 Interview Learning OS](learning-os.html)。总练习图：[统一练习脉络](practice-roadmap.md)。

## 评审结论

现有方案已经是优秀的“结构化备考课程”：目标岗位清楚，资料经过筛选，具备主动回忆、间隔复习、手写实现、项目证据、系统设计和 mock。它符合当前备考预期，但离“跨时代的新交互教育系统”仍有一层本质差距：系统知道课程结构，却不知道学习者此刻真正掌握了什么，也不能根据证据动态改变下一步。

综合评分：当前约 **6.8/10**。内容与练习设计强，自适应交互与学习数据弱。完成本次 V2 改造后，设计目标约为 **8.5/10**；仍不能把原型宣传成经过大规模学习效果验证的智能导师。

## 设计依据

- 检索练习不仅测量记忆，也能改善延迟保持；反复阅读可能提高主观熟悉感，却不等于长期掌握。[Roediger & Karpicke, 2006](https://pubmed.ncbi.nlm.nih.gov/16507066/)
- 间隔效果与目标保持时长有关，固定 D+1/3/7/14 是可用 baseline，但应根据成功率和目标日期调整。[Cepeda et al., 2008](https://pubmed.ncbi.nlm.nih.gov/19076480/)
- IES 的学习实践指南同时建议间隔、主动检索、深层解释问题、图文结合、抽象/具体表征连接，以及 worked examples 与独立解题交替。[IES Practice Guide](https://ies.ed.gov/ncee/wwc/PracticeGuide/1)
- 生成式 AI 的效果取决于交互设计。随机实验发现，无护栏的通用聊天界面可能让练习更容易，却损害之后的无辅助表现；有教师设计护栏的 tutor 风险更低。[PNAS, 2025](https://doi.org/10.1073/pnas.2422633122)
- 精心设计、与课程材料对齐的 AI tutor 在特定大学物理课程随机实验中取得了积极结果，但这不能直接外推到所有人和所有领域。[Kestin et al., 2025](https://pmc.ncbi.nlm.nih.gov/articles/PMC12179260/)
- UNESCO 强调人本、能动性、隐私、包容与对工具的验证；学习者不应被不可解释的推荐或数据采集接管。[UNESCO GenAI Guidance](https://www.unesco.org/en/articles/guidance-generative-ai-education-and-research?hub=66973)

因此，V2 不把“聊天更自然”误当作“学习更有效”，也不把完成题数、停留时间和 AI 生成字数当成成功指标。

## 从课程表升级为 Learning OS

### 1. 能力图，而不是章节目录

八个能力簇继续作为稳定地图，但每个练习成为带依赖的能力节点。节点至少记录：

- 主题、能力簇、题型、预计时间、前置节点。
- 原理、实现、诊断、迁移和表达五类证据。
- 当前掌握度、信心、最近作答、下次到期、提示次数、变式次数。
- JD 相关性、目标面试轮次和预计解锁价值。

周主题只提供边界和节奏，不再硬性决定每天题目。

### 2. 学习者模型，而不是完成百分比

每个节点的状态采用五维证据：

| 维度 | 问题 |
| --- | --- |
| Correctness | 结论、公式、shape 或代码是否正确？ |
| Reasoning | 是否能解释机制、不变量、假设与替代方案？ |
| Transfer | 换数据、约束、设备或产品场景后是否仍会？ |
| Communication | 是否先澄清、结构化、简洁并吸收追问？ |
| Independence | 使用了多少提示，能否无辅助完成 exit ticket？ |

总体 mastery 不能由平均分掩盖短板：Transfer 或 Independence 低于 3 时，节点最高只能标记为“可独立”，不能进入“可面试”。

同时记录 confidence。高信心低表现是优先修复的危险盲区；低信心高表现需要减少无意义重复并提高挑战。

### 3. Next Best Action，而不是固定 Day N

原型使用可解释的启发式优先级，不伪装成经过训练的知识追踪模型：

    priority = 0.35 × mastery_gap
             + 0.25 × JD_relevance
             + 0.20 × forgetting_risk
             + 0.15 × prerequisite_unlock
             + 0.05 × modality_variety

推荐卡必须显示“为什么推荐”。学习者可以改选，并记录理由。未来若积累足够交互数据，才考虑 Bayesian Knowledge Tracing 或其他模型；在单人小样本阶段，透明规则优于虚假的算法精度。

### 4. 六步交互回路

每个 session 使用同一状态机：

1. **Orient**：展示目标、时间、可验证产物和前置条件。
2. **Retrieve**：先闭卷预测或作答，不显示材料和参考解。
3. **Construct**：口述、编码、画图、debug 或做决策，产生真实证据。
4. **Challenge**：改变约束或情境，验证是否只记住表面答案。
5. **Feedback**：按 rubric 指出最大误差，必要时逐级给提示。
6. **Consolidate**：完成无辅助 exit ticket，记录信心、证据和下次复习。

它比“读 25 分钟、答三题”更接近真实能力形成，也使不同题型共享一套交互语言。

### 5. 分级支架，而不是立即给答案

提示只有三层：

- L1：指出需要检查的维度，例如 axis、约束、错误成本或 SLO。
- L2：给出模式或局部不变量，不给完整步骤。
- L3：提供部分 worked example，并逐步 fading；学习者必须补完关键决策。

完整参考答案只能在有过实质尝试且完成错误定位后出现。看过答案之后必须做一个新变式和一个无辅助 exit ticket。

### 6. 多模态交互，而不是聊天框包办一切

同一能力节点至少经历两种不同交互：

- **Explain**：90 秒口述和追问。
- **Build**：写函数、测试或伪代码。
- **Inspect**：阅读错误代码、训练曲线、trace、profiling 或架构图。
- **Decide**：在成本、延迟、质量、安全之间做明确取舍。
- **Simulate**：面试官、stakeholder、incident commander 或 code reviewer 角色模拟。
- **Teach-back**：用图或最小例子向非本领域同事解释。

“跨时代”不在于使用更多动画，而在于系统能让同一知识跨表示、跨角色、跨约束迁移。

## AI 教练契约

Learning OS 生成的教练提示遵守：

1. 先询问目标和当前判断；一次只问一个高价值问题。
2. 前 15–25 分钟不直接给完整答案。
3. 先让学习者预测，再运行代码、查看资料或给反馈。
4. 优先指出最大概念误差，不一次倾倒所有改进。
5. 通过反例、边界、变式和 why-not 检查理解。
6. 明确区分事实、推断、建议和不确定性；要求一手来源验证高风险结论。
7. 不把流畅表达等同于正确，不以鼓励性语言替代评分证据。
8. session 最后必须关闭帮助，完成无辅助 exit ticket。
9. 默认不接收客户、前雇主、未公开项目、PII、密钥或商业机密。
10. 学习者可拒绝推荐、调整难度、导出或清空本地状态。

## 评估指标

### 北极星指标

**Unaided Transfer Success**：在延迟、换问法、换约束且无 AI/资料帮助的情况下，达到目标 rubric 的比例。

### 领先指标

- Retrieval success：到期节点首次闭卷通过率。
- Hint dependency：每次成功平均使用提示层数。
- Calibration error：自信度与实际表现之间的误差。
- Transfer distance：同题复现、近迁移、远迁移分别是否成功。
- Evidence diversity：是否只有口述，还是同时有代码、测试、图、trace 和决策记录。
- Time to independent：节点从首次尝试到无辅助通过所需时间。
- Mock conversion：练习评分提升是否转化为随机 mock 提升。

### 反指标

- 完成题数、连续打卡天数、页面停留时长。
- AI 对话长度、生成答案数量、提示点击量。
- 刚看完答案后的即时正确率。

这些指标可以辅助习惯，但不能单独代表学习。

## 已完成的改进

- 创建本地交互原型 learning-os.html：能力图、可解释推荐、session runner、分层提示、迁移题、五维 rubric、信心校准、到期复习、本地证据日志、导入导出。
- 将[统一练习脉络](practice-roadmap.md)从静态五级阶梯升级为自适应六步回路。
- 将[六周计划](study-plan.md)的每日 90 分钟模板改为“检索 → productive struggle → 分层反馈 → 迁移 → 证据”。
- 保留原六周主题作为 curriculum guardrail，下一题由学习证据而不是打卡顺序决定。

## 尚未完成、不能假装完成的部分

1. **没有真实学习效果数据。** 需要至少 2–4 周使用后比较基线、延迟迁移和 mock。
2. **没有自动理解代码/口述。** 当前 rubric 由学习者或 AI 教练辅助评分；未来可接测试运行、语音转写和结构化 evaluator。
3. **没有可靠的知识追踪模型。** 当前是透明启发式；单人少量数据不足以支持复杂模型。
4. **没有真正的协作层。** 未来可加入同伴评审、mentor 校准和匿名 benchmark，但不能牺牲隐私。
5. **没有验证推荐权重。** priority 权重只是 V2 baseline，应根据实际 transfer gain 调整。

## 两周验证实验

不要直接相信 V2。用一个小型交叉实验验证：

- 选择 12 个难度相近节点，按能力簇配对。
- A 组使用旧的固定顺序和普通复习；B 组使用 V2 的先检索、分层提示、迁移和动态到期。
- 练习当日记录时间、提示、信心和得分。
- 7 天后无辅助、换问法测试；14 天后随机 mock。
- 比较 unaided transfer、hint dependency、calibration error 和 time to independent。
- 若 B 组没有实质改善，先审查任务配对、rubric 和支架强度，不为“新交互”概念辩护。

这一步决定系统是否真的更好，而不是看起来更先进。
