# Hello-Agents：从范式到可评测 Agent 的实践路线

资料：[datawhalechina/hello-agents](https://github.com/datawhalechina/hello-agents)（中文在线版：[Hello-Agents](https://datawhalechina.github.io/hello-agents/)）。本路线审计基于仓库 `main` 的提交 `6c616938c521c89bc4b2bf001bf237d259f1726b`，提交日期 2026-07-10；后续代码、依赖与在线内容可能继续变化。

目标不是顺序读完 16 章，而是把教程变成一条可面试、可运行、可诊断的证据链：`单步基线 -> ReAct / Plan-and-Solve / Reflection -> 最小运行时 -> 工具与上下文 -> 协议边界 -> 评测 -> 项目答辩`。

## 定位：实现实验室，不是第二条 Agent 理论主线

- [《深入理解 AI Agent》路线](ai-agents-in-depth-plan.md)负责运行时原理、Harness、上下文、工具、安全、评测和多 Agent 的主线解释。
- 本路线负责亲手实现三种经典范式、拆最小框架接口、注入故障、跑小型评测，并把项目变成可答辩证据。
- [Harness Engineering 路线](harness-engineering-plan.md)继续负责仓库地图、SPEC、机械约束、反馈飞轮与长期代码库治理。
- [Smol Course 路线](smol-course-plan.md)负责后训练；Hello-Agents 第 11 章 Agentic RL 只在模型训练/RL 岗选修，不重复进入默认周计划。
- 教程附录的面试题用于发现盲区，不把社区答案当标准答案；每条答案仍要经过一手资料、代码、trace 或实验验证。

## 快照、许可与运行边界

- 仓库当前目录包含 16 章主教程、额外章节、章节代码和社区共创项目；这些层级的完成度与维护质量不能视为完全相同。
- 仓库根许可证是 CC BY-NC-SA 4.0。学习笔记可以记录自己的总结和实验；若复制、改编或公开分发原文/图表/代码，先检查归属、非商业和相同方式共享要求，以及子项目或第三方依赖自己的许可证。
- 教程不同章节出现 `hello-agents==0.1.1`、`0.2.7`、`0.2.8` 等版本线索。每个实验必须单独建环境并锁定依赖，不把跨章代码直接拼进同一环境。
- 框架、MCP/A2A/ANP、模型 API 和 benchmark 都会变化。先固定本路线的仓库提交与依赖锁，再用对应项目的官方文档核对当前 API。
- 默认不下载大型权重、不跑全量 GAIA/BFCL、不调用付费搜索或 judge；先用 fake model、fake tool 和 12–30 条本地样本完成确定性测试。
- `.env`、API key、客户数据、个人信息和内部文档不进入学习仓库、答案卡或公开 trace。

## 学习依赖图

```text
HA-0 可验证任务与非 Agent 基线
  -> HA-1 三种范式与停止条件
  -> HA-2 最小框架 contract
  -> HA-3 工具、故障与确定性控制面
  -> HA-4 记忆 / RAG / 上下文流水线
  -> HA-5 MCP / A2A / ANP 边界
  -> HA-6 component / trace / end-to-end eval
  -> HA-7 单 Agent 优先的项目答辩
```

每次 Session 使用同一协议：闭卷预测 8 分钟，定向阅读 15–25 分钟，编码或画图 25–45 分钟，最后做一个换约束的 exit ticket。代码跑通只形成候选证据；D+1/D+3 零提示复测通过，才算掌握。

## 8 个核心 Session

### HA-0 · 先定义任务、环境与非 Agent 基线

- **阅读**：第 1 章只读 Agent 定义、类型与适用场景；第 16 章只读选题原则，不急着选多 Agent。
- **任务**：选择一个 1–2 小时能完成的窄任务，例如“读取 3 份本地 Markdown，抽取主张并生成带出处的差异表”。
- **先写契约**：输入、允许的工具、不可执行动作、成功判定、延迟/成本上限、不可回答条件和 12 条测试样本。
- **基线**：先实现固定 workflow 或一次 LLM 调用；记录成功率、错误类型、调用次数和耗时。
- **过关**：能回答“为什么这里需要 Agent”；如果固定 workflow 已足够，就保留非 Agent 方案，不为了使用框架增加自治。

### HA-1 · ReAct、Plan-and-Solve 与 Reflection 故障实验

- **阅读**：第 4 章三种范式；第 7 章 7.4 只看它们如何被统一接口重构。
- **实现**：用 fake model 与两个无副作用工具实现可重放状态机，显式记录 `state/action/observation/error/stop_reason`；先不要接真实搜索 API。
- **对照**：同一 12 条任务分别跑 ReAct、Plan-and-Solve、Reflection 和固定 workflow，比较任务成功、步骤数、无效调用、循环、重规划和成本。
- **故障注入**：格式错误、未知工具、工具超时、空结果、重复观察、计划过期、反思无增益、达到最大步数。
- **关键判断**：Reflection 不是免费纠错，Plan-and-Solve 也不是复杂任务的默认答案；必须用任务分布和停止条件证明收益。
- **过关**：不用“更灵活/更聪明”作结论，而能用 trace 和失败分母解释哪种范式适合什么任务。

### HA-2 · 从零画出最小 Agent 框架 contract

- **阅读**：第 7 章 7.1、7.3、7.5；抽取 `Message`、`Config`、`Agent`、模型适配器、`Tool`、`ToolRegistry`，不抄完整框架。
- **输出**：画出依赖方向和所有权；为每个接口写输入/输出 schema、错误类型、同步/异步语义、可观测字段与测试替身。
- **最小实现**：只保留一个 Agent loop、一个 fake LLM、一个 calculator、一个故障工具和内存 trace store。禁止在 prompt 文本里解析任意代码后执行。
- **版本测试**：模型提供商与工具实现通过 adapter 注入；测试不依赖网络、当前模型或真实 key。
- **过关**：可以替换模型和工具而不修改 loop；可以重放固定轨迹；未知状态会失败关闭，而不是静默继续。

### HA-3 · 工具、权限、幂等与恢复

- **阅读**：第 7 章工具系统；第 14 章只抽取 ToolRegistry 与搜索调度的工程边界；再回查 AID-4。
- **contract**：为一个只读工具和一个有副作用工具写 name、description、JSON schema、权限、timeout、retry、idempotency key、补偿、审计和人工升级。
- **故障矩阵**：区分“未执行”“执行失败”“超时但可能成功”“部分成功”“返回污染内容”；每种状态定义下一动作。
- **安全实验**：在工具结果中放入 prompt injection，验证它不能扩大权限、读取密钥或绕过确认。
- **过关**：模型输出只是未授权提议；控制面完成 schema 校验、授权、执行、审计和终止。盲重试不会制造重复副作用。

### HA-4 · 记忆、RAG 与上下文不是同一个模块

- **阅读**：第 8 章 8.2–8.4；第 9 章 9.1–9.3 和长程案例的故障部分。
- **画图**：把会话状态、用户记忆、组织知识、工具结果、可执行规则分开；标出写入、检索、压缩、引用、更新、删除和恢复来源。
- **最小实验**：实现 `Gather -> Select -> Structure -> Compress` 的确定性壳；比较原始历史、摘要、检索三种上下文，测任务成功、引用、token 与关键信息丢失。
- **对抗样本**：过期事实、冲突偏好、恶意文档、摘要丢约束、检索正确但生成没使用证据。
- **过关**：不把“长上下文”“向量库”“memory”当同义词；能解释时效、隐私、来源和删除如何穿过缓存与索引生效。

### HA-5 · MCP、A2A 与 ANP：先分清连接对象

- **阅读**：第 10 章先读 10.1，再按岗位选择 MCP 实战；A2A/ANP 只做比较卡。
- **比较卡**：分别写清协议连接的参与方、能力发现、消息/工具 contract、状态所有权、身份认证、错误传播和适用边界。
- **最小实现**：只实现一个本地、只读、无密钥的 MCP server/client；用 contract test 验证工具发现、schema、正常返回和结构化错误。
- **反例**：如果普通函数调用或内部 API 已经足够，不引入协议；“使用了 MCP”不自动获得安全、可靠或可观测性。
- **过关**：不把框架、协议和 Agent 拓扑混为一谈；能解释何时用直接工具、MCP 或 Agent-to-Agent 通信。

### HA-6 · 从 benchmark 名称回到可行动评测

- **阅读**：第 12 章 12.1；BFCL、GAIA、LLM judge 只抽取评估对象、verifier 与局限。具体版本回查各 benchmark 官方仓库。
- **三层矩阵**：component 层测工具选择/schema/参数；trace 层测步骤、恢复、权限与终止；end-to-end 层测最终任务、延迟、成本和高风险 slice。
- **本地小集**：从 HA-0 扩成 30 条，包含 simple、multiple、parallel、irrelevance、unanswerable、注入和部分失败；固定数据版本、seed、模型配置和 trace schema。
- **实验**：固定 Harness 换模型；固定模型逐一替换范式、工具描述、context policy 和 stop rule。报告置信区间与失败分母，而非只报总分。
- **judge 校准**：LLM judge 只评需要语义判断的维度；用人工标注小集检查一致性、位置/长度/风格偏差，并保留确定性 verifier。
- **过关**：每个失败都能路由到模型、上下文、工具、控制面或评测缺陷；知道公开 benchmark 高分不能替代自己的任务验收。

### HA-7 · Capstone：单 Agent 优先的研究助手

- **选题**：优先复用 HA-0 的窄任务，或从第 13/14 章的旅行/深度研究案例抽一个最小垂直切片；不复制完整前后端。
- **先单后多**：先交付单 Agent / 固定 workflow baseline。只有隔离、并行或专业化收益被实验验证，才增加第二个 Agent。
- **必须交付**：README、锁定依赖、12–30 条 eval set、架构图、状态机、tool contracts、trace schema、三条失败 trace、成本/延迟表和回滚条件。
- **故障演练**：过期来源、恶意网页、工具超时但成功、重复事件、上下文压缩丢约束、模型输出非结构化内容。
- **面试答辩**：12 分钟说明问题、基线、为何选择范式、系统边界、最大失败、评测、权衡与下一实验；准备一个“删掉 Agent 会怎样”的反方版本。
- **过关**：D+7 随机加入一个新故障，45 分钟内能定位、补测试、修复并解释残余风险。

## 三个岗位选修

### HA-X1 · 框架横评与低代码

第 5、6 章只在面试明确询问 Coze、Dify、n8n、AutoGen、AgentScope 或 LangGraph 时阅读。用同一任务比较抽象层、状态模型、调试、测试、部署、锁定和迁移成本；不做“功能数量排行榜”，也不背快速变化的 API。

### HA-X2 · Agentic RL

第 11 章只在 Agent 模型训练/RL 岗激活。先复用 [Smol Course 路线](smol-course-plan.md)的 SFT/eval 契约，再比较 SFT、GRPO 与 Harness 修复解决的不同问题。必须说明数据来源、奖励投机、credit assignment、训练资源、离线/在线评测与回滚；不能把训练 loss 或 reward 上升当任务成功。

### HA-X3 · 多 Agent 与社会模拟

第 13、15、16 章只在多 Agent/仿真岗位激活。先给单 Agent baseline，再测可分解性、上下文隔离、并行收益、消息丢失、共享资源冲突和错误级联。角色数量不是能力指标；每个子任务都要有独立可验证的交付 contract。

| 时机 | 激活内容 | 替换什么 | 交付物 |

## 面试追问链

1. ReAct、Plan-and-Solve、Reflection 各把状态与决策放在哪里？什么失败会触发重规划、反思或终止？
2. 一个最小 Agent runtime 必须有哪些 contract？哪些只是特定框架的便利抽象？
3. 工具超时但可能已成功时，为什么重试危险？幂等、状态查询和补偿怎样配合？
4. 长期记忆、RAG、长上下文、笔记工具和可执行规则各解决什么问题？
5. MCP、A2A、Agent 框架和多 Agent 拓扑的边界分别是什么？
6. 最终答案正确但轨迹越权或浪费十倍成本，评测应如何判定？
7. BFCL/GAIA 这样的 benchmark 能证明什么、不能证明什么？怎样映射到自己的产品任务？
8. 为什么 Reflection 可能放大错误？怎样用反思次数、增益和停止门槛验证？
9. 什么时候多 Agent 比角色提示或固定 workflow 更好？需要什么对照实验？
10. 如果更强模型上线后仍失败，你如何用 model swap、component ablation 和 trace 路由根因？

## 完成定义

- HA-1、HA-2、HA-6 各完成一次即时输出和一次 D+1/D+3 零提示变式复测。
- 至少留下一组可重放的 fake-model/fake-tool 测试，不依赖网络或 API key。
- 至少比较三种 Agent 范式与一个非 Agent baseline；结论包含任务分布、失败分母、成本和停止条件。
- Capstone 具备版本、依赖、评测数据、trace、失败注入、发布门槛和回滚条件，不以 demo 截图作为主要证据。
- 能把教程主张分成“仓库事实、作者解释、第三方规范、自己的实验结论”四层；遇到版本变化时可回查，而不是死记 API。
