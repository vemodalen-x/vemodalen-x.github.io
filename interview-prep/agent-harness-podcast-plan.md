# 《探秘 Claude Code，搞懂 Agent Harness》听辨与实践路线

资料：[Apple Podcasts 单集](https://podcasts.apple.com/cn/podcast/%E6%8E%A2%E7%A7%98-claude-code-%E6%90%9E%E6%87%82-agent-harness-%E5%AF%B9%E8%B0%88%E6%9D%A5%E6%96%B0%E7%92%90/id1729552193?i=1000766263837)；[小宇宙 Show Notes](https://www.xiaoyuzhoufm.com/episode/69f2e83fbb3ffa11e59dec82?utm_source=rss)。节目：十字路口 Crossing；嘉宾：来新璐；发布于 2026-05-05；时长 48 分钟。

这期节目最适合做 Harness 的“口语化总图”，不适合作为产品内部实现的唯一证据。学习目标是用它建立 `会跑 → 跑久 → 跑稳` 的诊断框架，再用代码、官方文档和反例校验节目中的强主张。

## 先明确来源边界

- 时间戳和三层框架来自节目 Show Notes；嘉宾对框架、产品和行业趋势的判断属于访谈观点，不自动等于 Anthropic 官方设计说明。

- [Claude Code 官方 Memory 文档](https://code.claude.com/docs/en/memory)可以验证 CLAUDE.md、auto memory、按需主题文件和加载限制；节目使用的“做梦”等比喻以及具体触发频率仍需按当前版本实测。
- [Claude Code 官方 Hooks 指南](https://code.claude.com/docs/en/hooks-guide)说明确定性动作与阻断应进入 hook。Prompt、CLAUDE.md 和 memory 是上下文，不是不可绕过的权限边界。

## 主张—证据矩阵

节目中最有价值的是可争论的主张。每条都按 `主张 → 机制 → 当前证据 → 反例 → 最小实验 → 暂定结论` 记录。

| 节目主张 | 学习时的处理 | 最小验证 |
| --- | --- | --- |
| Agent 产品由 Model + Harness 构成 | 作为边界模型使用，但继续拆出用户目标、环境和人类治理 | 固定模型消融工具、上下文、权限或反馈；比较失败类型而非只看总分 |
| Bash / CLI 提供强 action space | 视为教学与工程假设，不推出 CLI 永远优于 MCP/API | 同一任务比较成功率、token、延迟、可组合性、schema 错误、权限和审计成本 |
| 更多 context、更少 prompt control | 只在模型能力足够、任务探索性强且结果可验证时成立 | 比较 rigid workflow、自由 loop 与混合控制；按任务 slice 看质量和越权 |
| 长程任务需要压缩和接力交接 | 与上下文预算、任务持久化和恢复机制一致 | 注入窗口耗尽，检查 handoff 是否保留目标、不变量、进度、证据和下一步 |
| 半结构化 Markdown memory 会越用越聪明 | 官方资料支持 auto memory 与可审计 Markdown；“聪明”仍需行为评测 | 设置过期、冲突和恶意记忆，测试选择、合并、删除、来源与跨会话效果 |
| 好 Harness 应尽量不阻碍未来强模型 | 作为可替换性目标，不当作已证明事实 | 固定 Harness 更换两档模型；检查规则是否成为上限，同时保留高风险硬边界 |

尤其不要直接复述“CLI 训练占比”“模型领先时间”“未来公司形态”等节目数字或预测；面试中若没有一手证据，就明确标记为嘉宾观点。

## AHP-2 · 三层 Harness 设计实验

选择一个真实任务：修复仓库 bug、生成并发布报告、或处理带副作用的企业工单。用 50 分钟完成：

1. **执行层**：列出 read/write 工具、参数 schema、timeout、幂等、sandbox、审批和 observation。
2. **状态层**：定义静态前缀、运行轨迹、任务状态、handoff packet、memory/RAG，以及压缩后从哪里恢复原始事实。
3. **治理层**：定义 planner/builder/verifier 的权限是否分离、行为验收、停止条件、人工升级、trace 与成本门槛。
4. **故障注入**：工具超时但实际成功；上下文压缩丢失约束；memory 已过期；verifier 与 builder 同时拥有修改权。
5. **对照实验**：固定模型，分别移除一个执行、状态和治理机制；说明哪个观测能把故障路由回正确层。

**必须交付**：三层架构图、handoff packet、权限矩阵、四条失败 trace、主张—证据矩阵和 5 分钟面试讲解。

**过关**：不把“用了 Claude Code / MCP / 多 Agent”当作架构理由；每个组件都对应具体失败、验证与成本。

## 延迟复测题

1. “模型之外都是 Harness”为什么是有用但过宽的定义？给出更精确的系统边界。
2. CLI 的可组合性强，为什么仍可能不适合付款、医疗或企业写操作？
3. MCP 有 schema 和发现能力，为什么也不能自动保证工具可用性与安全？
4. 上下文压缩与 handoff 的最低保真集合是什么？哪些内容只保摘要会有风险？
5. CLAUDE.md、auto memory、Skill、hook 和 permission rule 分别解决指导、知识还是强制执行？
6. 为什么 builder 与 verifier 共用修改权限可能制造虚假通过？
7. 更强模型上线后，哪些 Harness 控制可以放松，哪些必须保留？如何用实验决定？
8. 一条 memory 让成功率上升但过期错误也增加，应如何决定保留、加时效还是删除？
