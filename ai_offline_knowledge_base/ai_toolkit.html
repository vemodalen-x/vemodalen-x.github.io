它解决什么问题

训练编排层，而不是新生成模型论文

统一实验入口

通过 YAML 把模型、数据集、network adapter、训练目标、优化器、采样、保存和日志放入同一 job。工程价值是让不同模型共用可追溯实验骨架。

显存约束下的适配

LoRA/LoKr、量化、低显存模式、latent/text embedding cache 和 gradient checkpointing 共同决定“能否跑”，但每个开关都可能改变速度、复现性或质量。

多种生成任务

README 快照同时列出 image、instruction/edit、video、audio 和 experimental 模型。任务形态会改变数据配对、采样器、评测维度和算力预算，不能共用一套默认参数。

训练运行面

CLI 适合版本化、批量与自动化；Web UI 适合配置和观察任务。两者最终都应落到可归档配置、checkpoint、样本、指标与失败日志。

配置解剖与决策边界

把参数分成任务、数据、适配、训练、模型和观察六组

配置段回答的问题实验检查
name / process / device这是什么 job，在什么设备上跑？先做最小 dry run；名称、设备与 process 类型写入实验记录。
network训练 LoRA、LoKr，还是选择特定层？记录 type、linear、linear_alpha、only_if_contains 与 ignore_if_contains。
datasets样本、caption、trigger、resolution 和 cache 如何进入训练？审计同名文本、分桶分布、caption dropout、重复样本与 held-out 泄漏。
train优化目标、步数、优化器与精度如何组合？固定 batch/steps/lr/dtype；flowmatch 等目标必须与模型示例一致。
model加载哪个 backbone，哪些部件量化或低显存运行？分别记录模型名、quantize/qtype、text encoder 精度、low_vram 与 cache。
save / sample / logging / meta如何保存、观察、恢复并追溯实验？固定 prompt/seed，保留关键 checkpoint，并把配置、版本和样本归档。

代表性配置不是通用最佳实践

示例快照中的关键取舍学习时必须验证
FLUX LoRA 24GBLoRA linear/alpha 16；flow matching；AdamW 8-bit；bf16；quantized model；512/768/1024 buckets；固定 prompt 与 seed；按 250 steps 保存和采样。先核对当前模型版本和显存，再消融 rank、学习率、分辨率与 cache；不要把“24GB”当作所有 FLUX 变体保证。
Qwen Image LoRA 24GB配置注释要求在该 24GB 方案中 cache text embeddings；包含 model/text encoder 量化、low_vram 与 flow matching。记录量化类型、cache 生成时机、训练吞吐、显存峰值与最终画质；比较关闭量化后的可行基线。
Wan2.1 1.3B LoRA 24GB示例按图像文件夹、单帧方式训练；配置注释认为它更适合角色而非动作，并使用 flow matching、sigmoid timestep 与量化 text encoder。角色一致性和动作/时序一致性分开评测；若目标是动作学习，不能用单帧结果替代视频训练证据。

LoRA、FullFT 与 LoKr

默认先用 LoRA 建立质量/成本基线。只有 LoRA 在充分 rank、目标层和数据审计后仍饱和，且算力与灾难性遗忘评测齐备，才进入 FullFT。LoKr 和层选择必须与同预算 LoRA 对照。

Cache 与量化

cache latents/text embeddings 减少重复前向但会固定部分数据变换；量化和 low_vram 降低显存，却可能改变吞吐与数值误差。每项优化都要保留无优化参考。

层包含与排除

only_if_contains 定义候选层，ignore_if_contains 负责排除且优先。运行前输出实际可训练参数名单，避免“任务完成但没有训练目标层”。

数据与 Trigger

README 约定图片和同名 .txt caption，分辨率通过 buckets 处理且不会上采样；[trigger] 可由 trigger word 替换。必须审计空 caption、重复图、泄漏和错误 trigger。

运行与证据边界

哪些是仓库事实，哪些需要本地验证

环境版本会漂移

README 快照要求 Python ≥3.10、推荐 3.12，并给出 PyTorch 2.9.1 / CUDA 12.8 wheel 的当前安装组合；这些精确版本会随仓库更新，应以当时 README 与 lockfile 为准。macOS Silicon 支持标为 experimental。

UI 是控制面，不是证据

当前 README 要求 Node.js >20，UI 默认位于 localhost:8675；远程暴露时应设置 AI_TOOLKIT_AUTH。job 启动后 UI 不必持续运行，但配置和日志必须归档。

中断与恢复要演练

CLI 可运行一个或多个 config，并支持恢复。README 警告在 checkpoint 正在保存时按 Ctrl+C 可能破坏该 checkpoint；测试时应验证上一个 checkpoint 是否可恢复。

“支持”不等于“同质量”

42 个名称只是 README 当前支持声明。模型许可、输入约束、训练目标、adapter 兼容性、显存和质量均需分别确认；experimental 项不能直接进入生产。
