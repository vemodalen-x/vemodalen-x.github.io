相邻仓库解决的问题不同

机制理解

micrograd 解释标量计算图；microgpt 压缩完整 GPT 算法；minGPT 展示最小 PyTorch 模块。目标是能手推和重写，不是追求训练吞吐。

训练复现

build-nanogpt 适合按 commit 复现 GPT-2；nanochat 才是当前 tokenization、预训练、微调、评测和推理的完整实验入口。

系统纵深

llama2.c 聚焦最小 C 推理；llm.c 聚焦 C/CUDA 预训练、数值对齐与性能。先保证 reference correctness，再优化 kernel。

Agent 与自动研究

llm-council 是多模型互评原型；autoresearch 是受限代码修改、固定预算、单指标筛选与回滚循环。两者都必须补独立评测与人工审计。

阅读纪律

  1. 先运行原始 baseline，并记录版本、硬件、数据与随机种子。
  2. 每次只改一个可解释变量；训练代码、评测代码和数据准备分开审计。
  3. 性能优化先做数值对齐，再报告 wall-clock、tokens/s、显存和质量。
  4. Agent 自动实验必须保留 diff、失败日志、预算和人工否决入口。

代码谱系与技术演进

从可视化神经网络到自修改研究循环

2014–2016
让深度学习机制变得可运行、可观察
convnetjs、char-rnn、neuraltalk/neuraltalk2 把浏览器 CNN、字符级序列模型和图像描述组织为可实验代码。能力重点：CV、序列建模、多模态原型。
2019–2021
从框架使用回到计算图、最小 GPT 与研究工具
micrograd 和 minGPT 用最小实现解释反向传播与 Transformer；arxiv-sanity 系列把研究发现流程也变成工程对象。能力重点：机制理解、可读 baseline、研究工作流。
2022–2024
完整复现语言模型训练与推理栈
Zero to Hero、makemore、nanoGPT、build-nanogpt、minbpe、llama2.c 与 llm.c 连接数据、tokenizer、训练、评测、C 推理和 CUDA 优化。能力重点：端到端复现与系统拆解。
2025–2026
从模型代码走向完整产品与自动研究闭环
nanochat 覆盖 LLM 全生命周期；llm-council、reader3、rendergit 探索 LLM 工作流；autoresearch 将代码修改、限时训练、指标判断和回滚交给 Agent 循环。能力重点：评测、成本、可审计 Agent 与研究自动化。

README 级注释与可验收产物

仓库学习轨道应该学什么验收产物
micrograd
当前基础入口		基础与反向传播【代码与 README】以标量计算图实现 reverse-mode autodiff，并在其上构造小型神经网络 API；适合逐步验证 forward、local gradient、topological backward 和参数更新。不依赖 autograd 重写 Value.backward，并用梯度检查验证一个两层 MLP。
nn-zero-to-hero
课程主线		基础与反向传播【课程 README】从 micrograd、字符级语言模型、MLP、激活与梯度、BatchNorm、手写反向传播、WaveNet 一路推进到从零构建 GPT。完成每讲 notebook 与练习，并保存一次激活、梯度和训练/验证曲线诊断。
makemore
教学实现		语言建模与 Tokenization【仓库与课程上下文】用字符级自回归语言模型逐步比较 bigram、MLP、卷积式层级结构和 Transformer，适合建立训练、采样与 NLL 评测闭环。在同一数据集上比较 bigram、MLP 与 Transformer，并解释验证损失和采样质量差异。
minbpe
教学实现		语言建模与 Tokenization【代码与 README】实现 byte-level BPE 的 vocabulary/merge 训练、encode、decode，并区分基础 tokenizer、regex 预切分与 special tokens。训练一个领域 tokenizer，报告压缩率、序列长度、特殊 token 与 UTF-8 往返正确性。
minGPT
历史教学实现		Transformer 训练【仓库简介】OpenAI GPT 训练流程的最小 PyTorch 重实现；适合读清模块边界，但当前完整训练实践应继续转向 build-nanogpt 或 nanochat。画出 embedding、attention、MLP、residual 和 loss 的张量形状与数据流。
build-nanogpt
逐提交复现		Transformer 训练【代码与 README】从空文件按清晰 commit 历史复现 GPT-2 124M，覆盖数据、训练循环和评测；该项目明确不包含 chat finetuning。按提交重建最小 GPT-2，并形成吞吐、显存、loss 与 HellaSwag 评测记录。
nanoGPT
已弃用，历史参考		Transformer 训练【README 2025-11 更新】约 300 行训练循环与约 300 行 GPT 定义的中型 GPT 训练仓库；作者已标记其为旧版并建议新项目使用 nanochat。把它作为简洁训练 baseline 阅读，并写出迁移到 nanochat 时新增的生命周期环节。
nanochat
当前主线		完整 LLM 生命周期【代码与 README】单 GPU 节点上的可修改 LLM 实验 harness，覆盖 tokenization、pretraining、finetuning、evaluation 和 inference，并用 depth 统一控制模型复杂度。跑通 tokenizer→预训练→微调→评测→CLI 推理，记录每阶段输入、产物、成本和失败点。
llama2.c
最小推理系统		LLM 系统与推理【代码与 README】在 PyTorch 训练 Llama 2 架构，再用单个纯 C 文件执行推理；重点是最小化地理解权重加载、tokenization、Transformer forward 与采样。给 run.c 标注内存布局与每层计算，并测不同上下文长度下的延迟与内存。
llm.c
训练系统纵深		LLM 系统与推理【代码与 README】用 C/CUDA 复现 GPT-2/GPT-3 系列预训练，并保留并行 PyTorch 参考与约千行 CPU fp32 版本，适合从正确性基线进入 kernel、混合精度和多 GPU。先对齐 C/PyTorch 数值，再 profile 一个 kernel，报告时间、带宽、显存和误差。
llm-council
实验原型		Agent 与应用【代码与 README】并行请求多个 LLM，匿名互评排序，再由 Chairman 合成最终答案；作者明确称其为周末 vibe-coded 原型且不计划维护，不应直接视为生产架构。用固定问题集比较单模型、投票、互评与主席汇总，并测成本、相关错误与偏置。
autoresearch
2026 前沿主线		Agent 与自动研究【代码与 README】Agent 只修改 train.py，在固定 5 分钟预算下训练并以 val_bpb 决定保留或丢弃实验；prepare.py 固定，program.md 由人定义研究组织与约束。默认环境以单张 NVIDIA GPU/H100 为基准，跨硬件结果不可直接比较。建立可回滚实验循环，保存假设、diff、预算、metric、失败原因和人工审计结论。

额外最小桥梁：microgpt pinned gist 用单个 dependency-free Python 文件呈现训练和推理完整算法；适合在 minbpe/micrograd 之后、PyTorch GPT 训练之前阅读。

6 周可执行学习计划

每周必须留下代码、指标或系统图

周主读核心任务验收标准
1micrograd + Zero to Hero 1手写标量计算图、拓扑反传、MLP 与梯度检查。与 PyTorch 的 forward/gradient 数值对齐，并解释一次梯度错误。
2makemore + Zero to Hero 2–7从 bigram 逐步到 MLP、BatchNorm、WaveNet 与 GPT。同数据上的 loss/采样对照、激活和梯度诊断。
3minbpe + microgpt + build-nanogpt实现 tokenizer，按提交重建 GPT-2 数据流和训练循环。UTF-8 往返测试、压缩率、模型形状图和最小训练日志。
4nanochat跑通 tokenization、pretraining、finetuning、evaluation、inference。完整 lineage：输入数据、checkpoint、评测、成本和失败样例。
5llama2.c → llm.c先读 C forward，再做 PyTorch/C/CUDA 对齐和一个性能 profile。正确性误差、p50 延迟、tokens/s、显存或带宽报告。
6llm-council + autoresearch实现受限自动实验循环与多模型交叉评测。可回滚 diff、固定预算、独立 verifier、失败分类和人工审计。
