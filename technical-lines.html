Tech Lead View

From project list to technical lines.

This page groups my project history by reusable technical capability rather than by private project names. The intent is to show how the work fits together as systems: model development, deployment, runtime engines, rendering, evaluation, and handoff.

Architecture

Define stable interfaces between data, training, export, runtime, rendering, and evaluation.

Delivery

Turn research outputs into prototypes, device builds, services, and repeatable delivery paths.

Handoff

Make complex AI systems debuggable, measurable, documented, and safe for other engineers to operate.

1. Vision model platform and deployment foundation

The shared layer that turns visual model development into a repeatable train, evaluate, quantize, export, and deploy workflow.

Project cluster

Segmentation and matting training framework, high-resolution matting experiments, model versioning, edge supervision generation, inherited model retraining, and model conversion tooling.

Tech stack

PyTorch, Lightning Fabric, OmegaConf, Kornia, OpenCV, ONNX, TFLite, TensorFlow/Keras bridge code, TinyNN-style QAT, post-training INT8 quantization, AI Edge Torch style export paths.

Tech lead signal

Own the contracts between datasets, model configs, losses, export formats, validation gates, and downstream runtime constraints. This is the foundation for moving from one-off model work to a platform that other tasks can reuse.

2. On-device vision systems

Native real-time vision systems where model output must become stable user-facing behavior under device constraints.

Project cluster

Real-time composition guidance, camera interaction engines, bokeh runtime modules, image format tools, cross-platform C++ builds, and device-side debugging workflows.

Tech stack

C++11/14, CMake, Android NDK, TFLite runtime, GPU delegate, OpenCV, Lucas-Kanade optical flow, FastCV, NEON, OpenCL, libyuv, pthread portability layers.

Tech lead signal

Design perception, tracking, state machines, fallback behavior, and runtime tuning as one system. The work is less about a single model and more about making real-time camera behavior predictable.

3. Computational photography and GPU rendering

Depth, segmentation, matting, and rendering pipelines that turn model signals into final image quality.

Project cluster

Depth-aware bokeh, optical highlight simulation, portrait enhancement, special effects rendering, motion blur prototypes, multi-frame portrait composition, and GPU-rendered image services.

Tech stack

OpenGL, GLSL, OpenCL, C++ rendering code, PyOpenGL, moderngl, TensorRT, ONNXRuntime, DepthPro-style monocular depth, matting backends, face detection, alpha compositing, HDR and tone mapping utilities.

Tech lead signal

Bridge the gap between model outputs and visual quality. A good camera AI feature needs spatial reasoning, rendering control, edge-case tuning, and performance awareness.

4. Agentic multimodal workflows

VLM/LLM systems for visual composition where reasoning needs structure, evaluation, and operating discipline.

Project cluster

Multistage visual composition agent, model-provider routing, structured output schemas, professional review logic, experiment reports, A/B evaluation, and reproducible debug bundles.

Tech stack

Python, OpenAI and Gemini APIs, JSON Schema, provider routing, structured outputs, workflow state objects, Langflow-style flows, pytest, ruff, loguru, image processing utilities, experiment summary tooling.

Tech lead signal

Treat agents as systems, not demos: explicit state, constrained outputs, cost-aware routing, failure handling, evaluation harnesses, and reproducible traces.

5. Data, evaluation, and simulation infrastructure

The data and evaluation layer that makes vision features trainable, comparable, and debuggable.

Project cluster

Trimap generation, edge supervision, hard-sample preparation, multi-frame composition data, interactive quality-control tools, device dump extraction, image format conversion, batch simulation, and model comparison reports.

Tech stack

Python, OpenCV, NumPy, Streamlit, FFmpeg-style media handling, img2dataset-style acquisition, multiprocessing, JSON review logs, model comparison scripts, visualization montages.

Tech lead signal

Make data quality visible. For vision systems, better workflows for data production, filtering, and evaluation often create more leverage than another architecture change.

6. Service delivery and production handoff

Deployment work that packages models and rendering into services, demos, evaluation bundles, and maintainable handoff paths.

Project cluster

Containerized portrait services, GPU rendering inside service environments, REST inference APIs, demo tools, cross-platform build notes, technical documentation, and operational handoff checklists.

Tech stack

Docker, FastAPI, Flask, Streamlit, TensorRT engines, ONNXRuntime, NVIDIA GPU passthrough, X11/EGL rendering contexts, REST payload design, release checks, reproducible run bundles.

Tech lead signal

Think beyond implementation: what must be configured, measured, rebuilt, documented, and handed off so the system survives outside the original developer's machine.
