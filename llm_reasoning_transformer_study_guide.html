1. CS 159：Large Language Models for Reasoning

CS 159 是 Caltech 2025 春季的 Advanced Topics in Machine Learning 课程，主题明确为“Large Language Models for Reasoning”。课程目标包括：理解不同推理任务、在应用中操作 LLM、解构论文、针对新推理任务提出挑战并完成研究项目。

课程主线

  1. 模型与接口：Transformers and LLMs。
  2. 行动能力：Tool Use & Agents，Search & Planning。
  3. 推理过程：Thinking & Planning、Self-Learning Agents。
  4. 任务域：Scientific、Mathematical、Spatial Reasoning 与 Visual Programming。
  5. 计算分配：Optimization、Inference-Time Scaling。

它训练的不是“会调用模型”

课程后半段以论文报告和项目为中心。90% 成绩来自最终项目，10% 来自论文展示。展示采用四角色框架：

  • Champion：提炼关键思想与优势。
  • Critic：指出最重要的局限或证据缺口。
  • Pioneer：提出新研究机会。
  • Entrepreneur：转化为产品或应用假设。

工程学习上的直接价值

课程把 reasoning 看作一个系统问题，不只是一条 prompt。你需要同时设计 任务分解、工具接口、检索/搜索、验证器、记忆、采样预算 与 benchmark。这正是从聊天机器人进入 Agent 或垂直推理系统时最常缺的一层。

3. Lil’Log：作为“机制解释层”阅读

Lilian Weng 自 2017 年起持续维护学习笔记。它不是单一课程大纲，而是一组高密度专题综述：每篇通常从问题定义、模型结构/目标函数，延伸到代表工作与限制。对 CS 159 学习而言，最有价值的是把“论文清单”变成可解释的机制网络。

A. Transformer、规模与推理效率

Attention? Attention! → The Transformer Family → Transformer Family v2 → Inference Optimization → Scaling Laws, Carefully。

用途：解释 attention、位置编码、归一化、KV cache、并行化和模型/数据/算力分配；与 taxonomy 的结构词条逐个对应。

B. Prompt、思维链与 Agent

Prompt Engineering → Why We Think → LLM Powered Autonomous Agents。

用途：把 CS 159 的 Thinking/Planning、Tool Use、Search 转化为组件：规划、反思、短期/长期记忆、检索和 API 调用。

4. Transformer Taxonomy：先建立 2023 年的技术坐标系

Transformer Taxonomy (the last lit review) 将其覆盖范围描述为：22 个模型、11 个架构变化、7 个 post-pre-training 技术、3 个训练技术，以及 5 个不属于上述类别的技术。它是一个个人运行式文献综述，按重要性与独特性粗略排序。

4.1 模型：不是背参数量，而是识别设计动机

  • 尺度与数据：GPT-3、Gopher、Chinchilla、PaLM、LLaMA。
  • 检索与外部知识：RETRO。
  • 多模态与通用 Agent：Flamingo、Gato。
  • 代码/任务特化：AlphaCode、Codex、Galactica。
  • 稀疏激活：GLaM、Switch。
  • 开放模型与多语：GPT-J、GPT-NeoX、BLOOM、OPT、GLM-130B。

学习问题：每个模型是在优化数据配比、知识访问、模态接口、任务域、参数激活还是开放可复现性？

4.2 架构变化：建立工程影响映射

变化核心影响
Multi-Query Attention共享 KV，降低推理 KV 内存与带宽压力。
Sparse Attention限制注意力连接，面向长上下文复杂度。
MoE稀疏激活专家，提升参数规模与计算效率的比值。
FlashAttention以 IO-aware 算法减少 attention 内存访问。
RoPE / ALiBi位置编码与长度外推的设计选择。
RMSNorm / DeepNorm、SwiGLU 等训练稳定性、深度扩展与 MLP 表达。
Tokenizers压缩率、语言覆盖与输入分布接口。

4.3 后训练：把 base model 变成可用系统

  • RLHF with PPO：偏好数据 → reward model → RL 优化。
  • Constitutional AI：用原则驱动自我批改与 AI feedback。
  • 特化微调：Minerva（数学/科学）、Codex（代码）。
  • Supervised Fine-Tuning / FeedME：人类示例驱动的指令跟随。
  • FLAN：以指令格式任务改进 zero-shot 行为。
  • CoT outputs 微调：将过程样本作为训练信号。

连接 CS 159：后训练给出推理与工具行为的“初始策略”，而 search、verification 与 test-time scaling 是进一步在运行时提升的手段。

4.4 训练与推理接口

  • 训练：超参数与 compute-optimal scaling、Pre-training with Human Feedback、μP。
  • 不宜强行归类：Chain of Thought、Tool Use、Fill-in-the-Middle、Top-k/Top-p/Beam、Tail-Free Sampling。

这组分类的实际意义是避免把“能力”误当成“单一架构属性”。例如 tool use 是系统接口；CoT 可是 prompt、监督数据或 search policy；sampling 影响探索和多样性，但不等于模型已学会推理。

时效边界：文章发表于 2023-03-30，且作者明确排除 systems/performance 与 alignment 的系统综述。因此它非常适合学基础坐标，却不应被当作 2026 年模型格局、长上下文、推理模型或 Agent 框架的完整指南；这些部分应由 CS 159 的 reading list 与 Lil’Log 的较新文章补齐。

5. 三份资源如何串成一条主线

阶段 1 · 模型底座

先理解“Transformer 的可变项”

读 Taxonomy 的模型与架构变化，再读 Lil’Log 的 Attention、Transformer Family v2。输出一张自己的模型卡：attention 形式、位置编码、norm、MLP、tokenizer、KV cache、训练数据与上下文长度。

阶段 2 · 训练与对齐

理解能力来自训练分布，而非单个技巧

对照 Taxonomy 的 scaling、SFT、RLHF、Constitutional AI，与 Lil’Log 的 scaling laws、人类高质量数据、reward hacking。输出训练目标、反馈来源、风险和评测指标四列表。

阶段 3 · 推理与 Agent

把模型预测转化为闭环决策

以 CS 159 的 Tool Use、Search & Planning、Self-Learning Agents 为主线，搭配 Lil’Log 的 Prompt、Why We Think、Agent 和 Open-Domain QA。输出一个带状态、工具、验证器、记忆和预算的 Agent 架构图。

阶段 4 · 任务与验证

在数学、科学、空间、视觉任务上证明它有效

从 CS 159 的 benchmark 与 readings 选择一个垂直任务。不是只展示几个成功样例，而是预先定义 success、cost、failure mode 和消融实验。

Transformer recipe
  └─ pre-training / post-training
      └─ prompt or task decomposition
          └─ search + tools + memory + verifier
              └─ inference-time compute budget
                  └─ benchmarked task outcome

7. 实验与研究选题

Agent × 浏览/检索

问题：搜索次数增加，何时真的提升事实正确性，何时只增加幻觉和成本？

方案：对照 direct answer、RAG、ReAct、带验证器的 search agent。

指标：准确率、引用可验证性、工具失败率、平均调用数、延迟。

Inference-time scaling × 验证

问题：额外采样/搜索预算在哪类题上最有效？

方案：对照单样本、self-consistency、best-of-N、search/verification。

指标：pass@k、预算-成功率曲线、验证器 false positive/negative。

Tool use × 安全

问题：一个工具 Agent 如何在错误参数、越权意图和不完整信息下保持可恢复？

方案：schema validation、权限层、dry-run、human approval、可审计 trace。

指标：任务成功、违规拦截率、误拒率、恢复成功率。

视觉/空间推理 × 程序

问题：程序化视觉工具是否比端到端多模态回答更稳定？

方案：对照 VLM direct answer、Visual Programming、工具增强 Agent。

指标：空间关系正确率、工具调用成本、可解释 trace 和错误归因。

8. 用 CS 159 的四角色框架读任何论文

Champion：它到底解决了什么？

  • 明确输入、输出、训练信号和评测任务。
  • 用一张图解释核心机制，避免复述摘要。
  • 区分理论贡献、工程贡献和 benchmark 贡献。

Critic：证据缺在哪里？

  • 主张是否由合适 baseline、消融和统计稳定性支撑？
  • 是否把 benchmark gain 误写成通用推理能力？
  • 成本、数据污染、提示敏感性、工具可靠性是否被报告？

Pioneer：下一个可检验问题是什么？

  • 改变的变量必须可控：数据、模型、prompt、搜索预算、工具或验证器。
  • 先写失败假设，再设计小实验；不要从“大而全 Agent”开始。

Entrepreneur：如何变成可靠产品？

  • 把外部 API、权限、超时、重试、日志和回退作为系统一等公民。
  • 将业务成功率与模型指标分开：正确率不等于可用性。

10. Thinking Machines Lab：把模型能力变成可复现实验与协作系统

Connectionism 是 Thinking Machines Lab 的公开技术博客。相较于前面三份材料，它最值得补入的不是另一份模型史，而是四个实践层面：训练数据分布是否与部署一致、微调如何兼顾成本与能力、模型怎样与人实时协作、实验结果能否被确定性复现。

10.1 On-Policy Distillation：稠密反馈落在学生真正会到达的状态上

On-Policy Distillation 对比了两种常见后训练弱点：RL 的反馈与学生轨迹一致，但通常稀疏；传统 teacher trajectory distillation 提供逐 token 的稠密监督，但学生可能不会走到这些教师状态。文章的核心方案是先采样学生轨迹，再让强教师对这些轨迹逐 token 评分并进行蒸馏。

与 CS 159 的连接：这是 Self-Learning Agents、数学推理和 tool-use repair 的训练版答案。不要只收集成功轨迹，也要覆盖学生的真实失败状态并给出细粒度纠错信号。

实践问题：教师评分的可靠性、长轨迹成本、学生探索覆盖和 reward hacking 仍须分开测量。

10.2 LoRA Without Regret：何时 PEFT 可以替代 Full Fine-Tuning

LoRA Without Regret 讨论 LoRA 与全参数微调的关系，并报告在小到中等规模的 instruction-tuning 与 reasoning 数据集上，若关键超参数与适配层选择得当，LoRA 可以达到与 FullFT 相同的样本效率和最终表现。

工程含义：LoRA 的价值不只是省显存；它还支持多租户 adapter serving、较小训练布局和快速迁移。它不等价于“所有训练都适合低秩更新”，特别是数据量接近预训练规模或更新需要高容量时。

建议实验：固定数据、训练 token 和 evaluation，比较 FullFT/LoRA 的质量、wall-clock、显存、adapter rank、作用层和可恢复性。

10.3 Interaction Models：把 human-in-the-loop 做成模型能力

Interaction Models 提出时间对齐的 micro-turn 设计：连续处理 200ms 的音频/视频/文本输入与输出，而不是把协作严格切成“用户完整输入 → 模型完整输出”的回合。系统用实时 interaction model 保持对话存在感，并把较长的 reasoning、tool use、browsing 等任务异步交给 background model，二者共享上下文。

与 Agent 的连接：这是对 CS 159 Agent 结构的补充。一个好的系统不应只有 planner 和 tools；还需处理并发输入、任务委派、进度呈现、可打断性、延迟预算和时间感知。

评测启发：除了任务完成率，应评测响应延迟、打断处理、上下文连续性、工具结果插入时机与跨模态安全行为。

10.4 Determinism 与训练/采样对齐：让研究结果可解释

Defeating Nondeterminism in LLM Inference 区分了浮点非结合性与实际推理非确定性的来源，并围绕 batch-invariant kernels、RMSNorm、矩阵乘与 attention 讨论如何获得更可重复的推理。Interaction Models 还强调 trainer-sampler bitwise alignment 对训练稳定性和调试的价值。

与推理项目的连接：若同一 checkpoint、seed 和温度不能稳定复现，on-policy RL、agent trace 比较、sampler 消融与回归测试都会被噪声污染。确定性应作为实验配置的一部分，而不是出现问题后才排查。

最小实践：固定版本/权重/seed/输入、记录硬件与 batch 组成、保存 logits 或 token trace、做跨 batch size 回归测试。

10.5 Modular Manifolds：从“调参”到优化几何

Modular Manifolds 从权重、激活和梯度的尺度健康出发，讨论将参数约束在流形上，并以 Stiefel manifold 上的 Muon 变体说明如何将优化器与约束共同设计。

何时阅读：当你已经能训练/微调模型，想进一步理解训练稳定性、条件数、更新尺度与 optimizer 设计时。它偏训练研究，不是 Agent 项目的前置知识。

10.6 Human participation：系统目标不应只测自主时长

The Future Worth Building Is Human 是技术方向说明，强调定制化权重、持续反馈、交互接口和分散式对齐。它提出一个对产品研究很有用的问题：系统是否增强了用户的判断与组织的本地知识，而不只是替人完成更多任务？

评测改写：除 autonomous task completion 外，增加 human override 成功率、反馈吸收率、可纠正性、决策可追踪性和用户长期产出等指标。

最重要的补充：CS 159 教你把 LLM 用于推理任务，Thinking Machines 的文章提醒你：一个成功的 trace 不是系统成功。真正需要评估的是训练分布、运行时分布、延迟、并发、重试、安全和可复现性是否同时成立。

11. Labelbox Blog：以环境、评测与反馈数据驱动 specialist agents

Labelbox Blog 的核心价值在于把 Agent 的“部署后再看效果”改写成持续学习闭环：真实或模拟环境 → 完整 trajectory → 多层评测 → 训练信号 → 再部署。这与 CS 159 的推理任务、Thinking Machines 的 on-policy distillation 和 Lil’Log 的 Agent 架构正好相接。

11.1 Recursion：企业 agent 的环境—评测—训练循环

Introducing Recursion 将 specialist agent 的开发描述为一个统一 RL 平台：用可执行环境重建工作流、工具、政策与边缘情况；以最终结果、中间决策和执行质量共同评分；再将 graded trajectories 用于 fine-tuning 或 RL。

工程要点：生产不是终点，而是新的数据分布。环境必须包含真实工具状态、权限、文件、失败路径与可验证产物；否则模型只是在 prompt benchmark 上过拟合。

文中的性能与成本数字为产品方在特定任务和设置下的报告，应作为案例而不是跨模型的通用结论。

11.2 GIM：从孤立题目转向集成推理

Meta’s GIM 的解读强调：高难度不一定来自冷门知识，也可能来自多种推理同时协调。文章介绍的 Grounded Integration Measure 将约束满足、歧义、状态跟踪、空间逻辑、意图理解和认识论判断放进同一道问题，并结合细粒度 rubric 与 Item Response Theory。

与 CS 159 的连接：数学、科学、空间推理不应拆成互不相干的单项分数。为项目设计评测时，要构造“约束会相互影响、错误前提需要被拒绝、状态会持续变化”的任务。

11.3 EchoChain：全双工语音里的双流推理

EchoChain 关注模型在响应生成中被打断、约束更新时能否修正活跃任务状态。它把流畅对话与推理鲁棒性区分开，提出 Contextual Inertia、Interruption Amnesia、Objective Displacement 三类失败模式。

与 Interaction Models 的连接：Thinking Machines 讨论如何构建实时交互模型，EchoChain 提供“交互时是否仍能推理”的评测问题。你的语音/实时 Agent 应同时测 latency、抢话处理和约束更新后的任务正确性。

11.4 Implicit Intelligence：用户没说出的约束也属于任务

Implicit Intelligence and Agent-as-a-World 指出，真实请求常被刻意简化；Agent 需要在环境中观察状态、推断未明示约束、在不确定时澄清或保守行动，而不只是机械执行字面指令。

设计启发：评测环境应显式写下 hidden constraints、可观察证据、可调用工具、违约代价和澄清机会。仅以“工具调用成功”判定 Agent 成功，会奖励鲁莽的直接执行。

11.5 安全评测：拒答率不是安全本身

The AI Safety Illusion 讨论 safety datasets 中显式触发词和近重复结构的风险，并用“intent laundering”检验模型是否只是识别了表面线索。文章的可迁移结论是：评测集应按意图、上下文、措辞和分布外变化分层，而不是只反复测同一种明显提示。

红队最小集：同一危险意图的直接表述、委婉表述、角色/上下文转置、跨轮拼接和工具调用版本；分别记录拒绝、泄漏、可操作性与误拒。

11.6 Monitorability：测试模型是否愿意被监督

Measuring Monitorability Disposition 提出一个更高阶的评测轴：模型是否会主动启用监控、在何种严重程度下报告、会选择哪种监督通道、是否会关闭监控。该文在其设置下报告，模型倾向选择较宽松的监控者，且关键严重度的自我报告不足。

系统启发：不能把自我报告或 CoT 当作天然可靠的监控信号。为高风险 Agent 设置独立审计、不可绕过的日志、分级人工复核，以及“是否请求监督”的单独评测。

将 Labelbox 加入项目验收标准

层必须定义常见错误
环境初始状态、隐藏约束、工具、副作用、权限、失败和恢复路径。只有静态 prompt，没有真实状态转移。
trajectory计划、工具调用、观察、重试、最终产物、耗时和 token。只保存最终答案，无法定位失败。
评测结果正确性、中间决策、效率、延迟、安全、澄清与人工接管。只用 pass@1 或单一 LLM judge。
训练来自真实失败状态的反馈、held-out 环境和回归集。将成功轨迹直接当作覆盖全部部署分布。
治理数据权限、审计、评测版本、模型/adapter 版本、可回滚部署。无法追溯某次模型行为来自什么数据和策略。
核心学习结论：模型能力不是独立变量。对 specialist Agent 来说，最可持续的优势通常来自能否持续构建更好的环境、评测和反馈数据，而不是一次性换成更大的 foundation model。
